## 2026-11-23 — The field application invoice save refuses job, blend-ticket and Split Billing invoices (release #2388 Sol HIGH 3)

- New migration `20270228200000_field_app_save_refuses_other_editors.sql` (not applied live; record in `docs/reference/migrations.d/`).
- The field application invoice save rebuilds an invoice from its fields and the farms Field Setup lists for them. Sent a job's invoices (whose farms come from the split saved on the job), it could cancel them and bill a different farm. Example: a job billed Farms A and B, Field Setup lists Farm C at 100%; saving A's invoice there cancelled A's and B's invoices and created one for C.
- Now that save refuses, with nothing changed, any invoice it did not build (no field rows of its own: job and blend-ticket invoices) and any Split Billing invoice: `FIELD_APP_WRONG_EDITOR` with a plain sentence. The screen already opens those invoices in other editors, so no current path is lost. A retry of an earlier successful save still returns its first result. Signed-in users also lose direct write access to field rows and their payer shares (reading is unchanged); only the two field-app save functions write them.
- Live 2026-11-23 (read-only): 3 field-application invoices, no job-made groups, no Split Billing invoices, and the faulty cancellation never fired.
