## 2026-11-19 — EPA batch fill re-checks the product at save time, in the database (issue #1976)

The EPA batch fill (PR #1975) checked in the browser, just before saving, that a product still had exactly one EPA number and no other proposal. That check was not atomic with the save, so two admins batching the same products at once, or an EPA number added meanwhile, could slip through.

- New migration `20270130100000_epa_batch_commit_checks_at_save` (local candidate, not applied): a new admin RPC `commit_epa_proposal_batch`, with `commit_epa_proposal`'s arguments. Under the save's own locks, taken in the same order (every app path that changes a product's EPA numbers takes the same product lock, so a change in flight is waited out), it re-makes the batch screen's whole decision and refuses with `EPA_BATCH_NOT_ELIGIBLE`, writing nothing, unless the product's only EPA number is the proposal's, it has no ingredient row, no other proposal for that number is proposed, held or rejected, no other lookup of it is running or ever failed, EPA's record is not flagged, a distributor's or cancelled and its name matches a current app name, every ingredient is a plain add with a CAS number and a percent (100 at most in all), and the label, re-sorted now, has only blanks, confirmations and matches; `EPA_BATCH_DECISION_INVALID` when the decisions would write anything but an ingredient add. Then it calls `commit_epa_proposal` unchanged in the same transaction. The product page still uses `commit_epa_proposal`.
- The batch screen saves through the new RPC and shows a refusal as "Needs a person: Refused at save: <reason>; the proposal waits for a person", instead of an error that stops the run.
- Proof: `node scripts/smoke/prove-epa-batch-commit-real-schema.mjs` (EPA_BATCH_COMMIT_PROOF_PASS), including the hole before the change, a race with a brand carrying a second EPA number (the save waits, then refuses) a two-admin race (the first save wins, the second admin's save is refused), and each other check (label left to its default, name mismatch, a label fact edited since the lookup, another lookup running or failed). Screen: `src/lib/epaBatchFillRun.test.ts`.
- Not verified: a live run (the migration is not applied anywhere but the disposable prover database).
