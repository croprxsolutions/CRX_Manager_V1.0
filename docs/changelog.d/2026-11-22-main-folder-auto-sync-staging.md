## 2026-11-22 — Sessions keep the main checkout in sync with staging

- `.claude/hooks/session-staleness.mjs`: when the main checkout (`C:\CRX_Manager`, where every session's hooks load) is on `staging`, each session start fetches `origin staging` (explicit refspec, `--no-tags`, `--no-write-fetch-head`, full ref names, `GIT_*` variables dropped) and, at even one commit behind, tells the session to catch it up first: check that no uncommitted file changes upstream, confirm the folder is still on `staging`, then `merge --ff-only --no-overwrite-ignore <fetched commit>`; any refusal, a lock file included, goes to Mason (never delete a lock). A failed fetch is named in the warning. Local commits not on staging are flagged for Mason instead. Off `staging`, the old far-behind-`origin/main` warning is unchanged. Found when the folder sat 19 commits behind staging and still ran the owner-approval check fixed in #2290.
- Warn only, never a background merge (Mason, 2026-11-22): an advisory Sol review showed an automatic update at session start could move the wrong branch, overwrite ignored files, or be cut off half-way by the hook timeout.
- Tests: `.claude/hooks/session-staleness.test.mjs` fetches a real bare origin under a narrowed refspec with a decoy `origin/staging` tag, and covers behind (instruction, folder untouched), the prescribed merge refusing to overwrite a locally ignored file that staging starts tracking, up to date (silent) and local commits (flagged for Mason).
