## 2026-11-01 - Keep Supabase filter values out of Sentry request breadcrumbs

- Sentry breadcrumbs for network requests now drop everything from the first `?` or `#` and show `?[REDACTED]` instead. This is one `beforeBreadcrumb` filter in `src/lib/sentry.ts`, so it covers every read, not only payments. It applies to Sentry's own `fetch` and `xhr` breadcrumbs and to the `supabase` breadcrumb that `src/lib/db.ts` adds, which recorded the same values. Method, path and status stay, so an error report still shows which request failed.
- Every `fetch` and `xhr` breadcrumb is filtered, whatever its host, so the filter does not depend on matching the Supabase address.
- Proof: a production build of the real `sentry.ts`, `db.ts` and `findDuplicatePayment`, run in a browser against local stand-ins for Supabase and Sentry with made-up values. The raw report on main held the customer id 12 times and the amount 2 times; with this change it held neither, and the 200, the 500 and the dropped-connection breadcrumbs all kept their path and method.
- Not covered: this removes query strings from request breadcrumbs and nothing else. The rest of a Sentry report is unchanged, including request paths, page addresses and the data the app attaches on purpose. Reports already stored in Sentry keep what they recorded, and a browser still on the old bundle sends the old breadcrumbs until it updates.
