## 2026-11-19 - Signed-in users can no longer change spray jobs directly (#1979 PR C)

`20270131110000_jobs_direct_writes_removed.sql` removes direct INSERT, UPDATE, DELETE and TRUNCATE on `jobs` (table and every column) from signed-in users and anon, and drops the policies `jobs_insert`, `jobs_update` and `jobs_delete`. Decision (Mason, 2026-11-19, "close it"): every job change goes through a checked server function, and no one can mark a job completed without the completion step; admins' unused direct hard delete goes too. The migration refuses to run if live's job write permissions differ from the documented starting state, so the rollback can always restore exactly what was there. Reading jobs is unchanged, and so are the server functions, which run as the table owner. No row changes. Apply only after the screen PR (B) has been on production long enough that no open tab runs the old screens: an old tab's save is refused and nothing is saved; a refresh fixes it. Proof: `scripts/smoke/prove-jobs-direct-writes-removed-real-schema.mjs`. Rollback: the migration header restores the exact grants and policies (a permission change; needs Mason's approval).
