# Brand paperwork correctness contract (#1853)

## Outcome and authority

- An ordinary invoice line whose billed quantity differs from the whole delivery snapshot shows each recorded brand name and EPA number, but no per-brand load quantity. If every covered trip has picks that reconcile, it says exactly `Full-load brand amounts are on the delivery receipt.` If picks do not reconcile, the existing picked-versus-delivered mismatch note takes that sentence's place: the receipt then also withholds amounts. If any trip has no recorded brand, `Brand not recorded` prints without claiming the receipt has full-load amounts. The invoice's stored quantity, price and total do not change. Repeated `brand_key` values across trips show once when amounts are hidden. The EPA column keeps its current formatter.
- A Bill Split payer's invoice retains the existing explicit `on the load` quantities. Both the screen and every PDF route identify that case from the invoice's stored type, group and delivery, using `isBillSplitInvoice`, including a one-payer remainder or a voided invoice. These are load amounts, not the payer's billed share; no brand allocation is inferred.
- A pre-delivery load sheet whose picks do not add up to its **planned** line quantity shows names without amounts and exactly `Brand amounts do not match planned load: 4 of 5 picked` for a 4-of-5 example. The paper-info result carries that planned target with the picked total, so the hide decision and printed denominator always use one value, even if `quantity_delivered` is already set. A completed delivery receipt keeps its existing delivered-quantity wording. The same pre-delivery receipt PDF follows the load-sheet wording. This replaces the local comment that withheld a pre-delivery note to avoid falsely calling planned quantity delivered; it does not reverse a recorded Mason decision.
- Delivery paper reads every relevant `completed`/`corrected` brand event or fails visibly; a capped first page must never silently omit a later correction. This preserves the existing event-type filter and print failure behavior, including a batch failing as one job. `set` is allowed before completion; `reviewed` changes office review state, not the pick's name, number or quantity and does not confirm a stale completion. `edited` and `line_removed` are pre-completion editing/deletion history, not a corrected post-completion pick.

This is print/read behavior only. Existing invoice saves, posting rules, delivery completion, RUP capture, permissions and financial arithmetic stay with their current database paths. `_invoice_line_brand_allocation` already assigns partial quantities for the internal restricted-use register; this change does not copy that allocation onto customer paper. The invoice states its billed quantity, while the delivery receipt states full-load brand quantities. No migration, new permission, or new dependency is needed. Expected files: `supabase/functions/_shared/brandNotes.ts`, `supabase/functions/_shared/pdf/invoicePdf.ts`, `src/lib/invoicePdf.ts`, `src/pages/InvoiceDetail.tsx`, `src/lib/deliveryBrandPaper.ts`, focused tests, and the two delivery PDF callers.

## State and failure

- Compare the saved `invoice_items.brand_lines` delivered total with that displayed line's `invoice_items.quantity` in whole ten-thousandths, matching the established brand quantity rule. Distinct delivery lines contribute once. If any other displayed line on the **same invoice** carries the same `delivery_item_id`, suppress amounts on both lines even when either line's own quantity equals the full snapshot: printing the same load twice would double it. The database snapshot writer supplies non-null `delivery_item_id` from `delivery_items.id` (`20270106110000`, `_invoice_line_brand_lines`); an invalid or absent snapshot is not a source for new amounts. A missing brand snapshot keeps the existing no-note behavior. Existing per-trip picked-versus-delivered mismatch notes remain.
- On an ordinary mismatch, suppress every per-brand amount, including a multi-trip snapshot where only one trip's brands are recorded. Never distribute brands over a partial invoice in this print formatter. The screen uses its currently shown row quantity; Print and Email re-read saved invoice lines, so an unsaved edit may make the preview differ until saved.
- A Bill Split payer still identifies full-load amounts as `on the load`. The explicit label is the distinction from billed quantity.
- A failed or incomplete event page fails the print or whole selected batch rather than returning partial paper. Reads are ordered by the unique `seq` primary key and use the existing counted paging helper. Its second full read confirms multi-page results; no `id` alias is needed for this append-only event stream. The current print rule uses completion plus later correction history.
- There are no new writes or lifecycle transitions. Old rows with null `brand_lines` print as before; a recorded empty list still says `Brand not recorded`. The snapshot writer excludes credit memos, so those keep null `brand_lines`. A later brand correction affects only paper reprinted after it is read.

## Delivery

This feature branch targets `staging` and needs focused proof, full project checks, Luna and a clean Sol review because shared PDF code is on the Sol list. This work stops before push, PR, merge or deploy as requested. `send-email` bundles the shared invoice PDF: updating the web app alone does not update live emailed invoices. A later release must explicitly approve and deploy `send-email` before emailed and downloaded invoices can be claimed consistent in production. `send-delivery-receipts` uses the unchanged completed-receipt output, so it does not need a deployment for this change. The deferred email release gap is recorded in this plan and the change's changelog note.

## Proof cases

- **Ordinary partial invoice:** saved snapshot totals 5, billed quantity 3. The screen and rendered invoice PDF show brand names and EPAs without brand quantities, and point to the delivery receipt for full-load amounts. Synthetic browser and PDF render proof using several branded lines to check wrapping.
- **Ordinary whole-load invoice:** saved snapshot and billed quantity are both 5. Names, EPAs and per-brand quantities still print. Focused unit and rendered PDF proof.
- **Bill Split payer:** payer quantity differs from full-load snapshot, including a group with only one active payer in the read. Its brand quantities still print with `on the load` on screen and PDF; no allocation changes. Focused unit and rendered PDF proof.
- **Two trips and bad picks:** a mismatch within either trip keeps its existing warning even if trip totals could cancel; a partial invoice still hides all brand amounts. Focused unit test.
- **Repeated whole-load snapshot:** two displayed lines each carry the same 5-unit delivery line, and each bills 5. Neither prints a brand amount; names and EPAs remain. Focused screen and PDF test.
- **Pre-delivery load sheet:** picks of 4 against a planned 5 (even if `quantity_delivered` is 3) show names, no per-brand amounts, and the exact 4-of-5 planned-load note. A completed receipt still says delivered. Synthetic rendered PDF proof.
- **Event pagination:** more than one server page includes a later correction; the correct brand is printed. A failed page returns an error and no partial paper. Focused loader test with a capped-page mock; local real-schema read if available.
