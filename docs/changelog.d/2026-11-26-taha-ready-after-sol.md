## 2026-11-26 - A clean Sol now labels our lane PR for Taha automatically

- New `.claude/hooks/taha-ready-after-sol.mjs`: when a clean Sol proof is written, and after a push, `gh pr create` or `gh pr ready`, an open, non-draft lane PR of ours whose current head a clean Sol covers gets `ready-for-taha` and Taha's review request. The Taha ready bot cannot see Sol proofs, and agents kept forgetting the manual step (Mason labelled #2610 by hand). Best-effort: a gh failure prints the manual command and never fails the proof or the push.
- "Covers" is the merge gate's own rule (`proofValidForMerge`): a clean Sol of the current head or of an earlier commit of the PR, so a fix pushed after Sol asks Taha again too (Mason asked to close that gap the same day). Sol runs with findings Mason accepted do not count.
- Proof: `node .claude/hooks/hook-router.test.mjs` (118 assertions); a dry run against the open PRs (label calls intercepted) would have labelled #2643, #2638, #2610 and #2452. #2638 was covered only by a Sol of an earlier commit.
- After Taha's review the same day: it no longer re-asks him when his earlier Approve carries over (staging catch-up, `docs/` note, restamp); it asks GitHub the same carry-over question as the bot. Coverage now asks GitHub's compare like the merge gate, so a staging tip this checkout has not fetched no longer hides a label. A push GitHub has not caught up with is asked about once more. When a clean Sol proof is on disk but the hook cannot finish, it prints one "not labelled for Taha yet" line with the manual command. One 15 s deadline covers all its calls, and the PostToolUse router limit rises from 20 s to 40 s so it and the DIRTY-PR warning both fit. The proof reader and the GitHub ancestry answers have their own tests (138 assertions).
- Taha's second pass and the Codex bot: an unreadable file list now prints the manual line instead of reading as "not lane". A carry check that runs out of time says to re-ask him only if the push changed code. The review request is sent before the label, and a label failure after it says exactly that. `gh pr ready <n>` asks about PR n on its own head. 143 assertions.
- Taha's third pass: when the lane can't be told (no file list, or only unreadable migration SQL), the line says to ask him only if the PR is in his areas. The "he signed off earlier" line appears only when he did. A literal `cd <dir> &&` before `gh pr create` / `gh pr ready` is followed. 147 assertions.
- Codex bot: like the merge gate, an earlier commit's Sol covers the head only when the later commits stay off the Sol list (`solRiskOnGitHub`); an unreadable comparison is "unsure", never covered. A 250+ file list counts as lane unknown. 154 assertions, run on Windows and on Linux.
