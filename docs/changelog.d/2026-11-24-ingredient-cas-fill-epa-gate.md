## 2026-11-24 - Ingredients: an admin can add a missing CAS on an EPA-numbered product's ingredient

- Migration `20270304150000_ingredient_cas_fill_passes_epa_gate.sql`: re-issues `_edit_active_ingredient` so that an edit of the CAS alone (fill, or correct a typed one) is no longer refused with `CHEMISTRY_FROM_EPA_ONLY` when a product using the ingredient has an EPA number. Before, an ingredient the EPA lookup added without a CAS (EPA gave none) could never get one; the EPA review itself asks the admin to "correct the ingredient to link them".
- Limits (Sol review, 2026-11-24): a CAS that an EPA proposal gives stays locked on an EPA product, and, by the newest EPA proposal per product and number, the typed CAS must be the number EPA gives the ingredient and must not be a number EPA lists under another name (`INGREDIENT_CAS_NOT_EPA`). So a typed CAS never contradicts EPA, and a mistyped one can be corrected with the same screen.
- Unchanged: an EPA-given CAS, the acid fields, or a mix of fields still refuse on an EPA product; admin only; reason and evidence still required when products use the ingredient; CAS format, check digit and CAS-taken checks; the ingredient event and one `corrected` chemistry event per affected product. Product rows (strength, source, modes of action) are not touched.
- Screen: Ingredient review -> Needs CAS -> Add CAS already calls this path; its preview now shows the change instead of "would be refused". The preview's product note reads "has an EPA number" instead of "EPA-confirmed" (the number alone does not mean EPA confirmed the chemistry).
- Proof: `node scripts/smoke/prove-ingredient-cas-fill-epa-gate-real-schema.mjs` (`INGREDIENT_CAS_FILL_PROOF_PASS`, local Docker) and the local test copy in a browser.
- Not verified: the staging database (applied by the staging DB job after merge). Not applied live.
