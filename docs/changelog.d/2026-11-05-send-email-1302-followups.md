## 2026-11-05 — send-email: #1302 review follow-ups (not yet deployed)

- Sales reps can no longer send `statement` or `ar_reminder` emails; only admins can, matching the A/R Aging page (Mason's decision on Taha's #1302 review question).
- Two retries of the same failed email at the same moment send it once: a retry claims the log row only while it is still `failed`, and two first sends racing on one key get "already in progress" instead of an error.
- The call to Resend gives up after 30 seconds. An error reply marks the email `failed` (Resend never stores a failed request, so a retry is safe). No answer, a dropped connection or an unreadable OK reply may mean the customer already has it, so the row stays `pending` with the reason written on it and the caller gets 504 `needs_reconciliation`; the existing pending check refuses a re-send under that key until someone checks Resend. This deliberately differs from the review's "mark it failed": a failed row would allow a blind second send.
- `supabase/functions/send-email/send_email_test.ts` runs the real function against an in-memory database and Resend: wrong-customer record, reused key, legacy key dedupe, rep refused / admin allowed on a statement, both races, a timeout, an unreadable OK reply and a non-JSON error reply. CI's Deno test step now allows only the named settings the function reads (`--allow-env=...`).
- Takes effect only when `send-email` is deployed, on Mason's approval.
