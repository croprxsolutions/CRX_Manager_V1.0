KI-76: sale lines with no unit could never get a return credit. A blank unit is now filled from the order line, else the product, when the line is written; it never stops a delivery from completing; posting refuses a sale line that still has no unit, with a message staff can act on; and `create_invoice_from_order` refuses an order line with no unit.

**What changes.** A unit is blank when NULL or only spaces, tabs, line breaks or non-breaking spaces.
- New order line (or product change) with a blank unit takes the product's unit (`trg_fill_order_line_unit`, `_fill_order_line_unit`).
- Sale invoice line (a product line, with or without an order line), written with a blank unit, takes its order line's unit, else the product's (`a0_fill_invoice_line_unit`, `_fill_invoice_line_unit`; runs before every other BEFORE trigger on `invoice_items`). A line with no order line is filled only on a chemical sale. Return-credit and negative lines are left alone. Never refuses, so delivery completion and the unbilled-delivery invoice cannot fail on it.
- Moving a chemical-sale invoice into `posted`, `paid` or `overdue` refuses while any positive, non-credit product line has a blank unit (`zz_refuse_post_blank_unit_line`, `_refuse_post_blank_unit_line`, `INVOICE_LINE_UNIT_MISSING`, naming the lines; Mason 2026-11-10: no sale line posts without a unit). Field-application and misc-charge invoices are not checked. Fix: set the product's unit, save the draft, post.
- A delivery line inserted on a quick delivery always records its product's own unit, whatever unit the request named; a later direct edit keeps the unit it was recorded in, or takes the new product's unit if the product changes (`a0_lock_quick_delivery_line_unit`, `_lock_quick_delivery_line_unit`; Mason 2026-11-10). Never refuses; the app already sends the product's unit; live had 0 quick-delivery lines.
- Saving a draft (`save_invoice` -> `_save_invoice_scoped_impl`) rewrites its lines, then restores each order-linked line's lineage by sort order, product and unit. A line saved with no unit is now filled when rewritten, so that match failed (`GENERATED_INVOICE_LINEAGE_RESTORE_FAILED`) and the draft could not be saved (CodeRabbit, 2026-11-11; container-confirmed). The match now accepts the filled unit when the saved unit was blank; any other unit must still match. Body otherwise live's (md5 `12272e4be85f18a7772d20a59d1ddf88`, `20261118110000`); settings, owner and grants unchanged.
- `_create_invoice_from_order_impl_20260718` refuses an order with a blank-unit line before writing anything (`ORDER_LINE_UNIT_MISSING`); a refused call stores no receipt, so the same key works once fixed.
