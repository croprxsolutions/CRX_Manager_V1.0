PAR-2 (Stage 2 build sheet §5.1): group existing products into parents, only through an approved proposal. REQUIRES `20261108120000_product_parents` and `20261110150000_product_parent_stock_units` (both live); its preflight pins the installed bodies of `upsert_product_brand` and the ten PAR-1 helpers it calls (and checks that `_product_parent_size_role` and the replay helpers the brand writer calls exist), refuses if any new table already exists, and refuses if a size PAR-1 already grouped has its own legacy brand rows (live had none on 2026-11-05), so in any of those cases the one-transaction apply changes nothing.

What it does:
- New tables, RLS on, `SELECT` only for `authenticated` and no write grant for any role: `product_parent_proposals` (one row per build, one open at a time; admins read), `product_parent_proposal_groups` (one proposed group per row with allow-listed member fields only, no cost, price or stock; admins read; both carry `updated_at`), `product_parent_brands` (a parent's brand list; retired is final), `product_parent_brand_events` (append-only, a trigger refuses update, delete and truncate) and `product_parent_brand_sources` (every moved legacy brand row mapped to one parent brand). The last three are read by any active user.
- New admin writers, each with `p_idempotency_key` replayed through PAR-1's `_product_parent_replay` and authorized before the replay lookup: `build_product_parent_proposal`, `approve_product_parent_groups`, `hold_product_parent_group`, `reject_product_parent_group`, `upsert_parent_brand`. New read `get_product_brands` (any active user). Twelve private helpers with no API-role EXECUTE, among them the grouping switch `_product_parent_grouping_open()`.
- Grouping (§5.1): same base name (size, pack and container words removed; strength words such as "4L" or "4G" kept; grams only when written with a space, "500 g"), same form and, for seed or each, the same stock unit, and never two different EPA numbers. Same EPA number under another name is a flag. A group with some blank EPA numbers, an unreadable EPA number, no form, no name left, or a name that differs from another only by a strength token is held. Building a proposal groups nothing; the build holds its candidate sizes still (FOR SHARE) while it reads them, so each group and its stored snapshot use the same values (Codex App finding on PR #1555).
- Approval locks every member row of every named group first (group IDs compared as UUIDs, so any spelling of an ID takes the same locks), recomputes each group from those rows and refuses the whole call if anything changed since the build (rate, EPA number, brand, active flag) or if its sizes no longer share one base name, form, stock unit and EPA number, if a conflict has no exact pick, if an owner-confirmed group lacks the tick, if a tote has no answer, if a shop-filled tote is not fertilizer or not filled from the group's bulk size, if two sizes would be bulk, if the chosen category is retired, or if a size's per-acre prices are not the previewed ones. While rates are locked, a group that would change any size's rate is refused. It copies the picks onto every size through PAR-1's `_copy_parent_to_size` and writes one `created` parent event per group. It never writes EPA numbers or label facts. A shop-filled answer is only recorded; fill-time unit rules stay with `fill_tote_from_bulk`. Legacy brands move to the parent list; identical rows share one parent brand, differing variants need a pick, unpicked variants are kept retired.
- `upsert_product_brand` re-issued (same signature and grants): after the receipt lookup it takes a product-row lock that waits for approval (`FOR NO KEY UPDATE`, which leaves foreign-key checks on that product free) and, once the grouping switch is on, refuses a grouped size with `PRODUCT_BRANDS_BELONG_TO_PARENT` (nothing written). Ungrouped sizes, and every size while the switch is off, behave as before.
- Grouping switch, shipped OFF (the postflight refuses it on): `approve_product_parent_groups` and `upsert_parent_brand` refuse `PRODUCT_PARENT_GROUPING_NOT_OPEN`, `get_product_brands` reads every size's own list, and the old brand writer edits every size. So no brand moves to a list today's product screen cannot show. The PAR-2 screens PR's migration turns it on (replaces the body with `SELECT true`) after settling any brand rows a PAR-1 grouped size gained meanwhile. A build with nothing left to decide is closed at once; `upsert_parent_brand` refuses an inactive parent.

No existing row, grant or policy changes. No group is approved by this migration.
