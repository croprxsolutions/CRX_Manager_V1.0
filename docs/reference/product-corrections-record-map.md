# Product label corrections: record map

**Owner rule (2026-10-28):** When a product's re-entry interval (REI) or pre-harvest interval (PHI) is corrected, open jobs with filled-in chemical line values offer to update them. Blank lines already follow the product. Posted invoices never change.

| Record | Copies what | When | Does a product correction reach it? |
|---|---|---|---|
| `job_product_epa` | `epa_registration` (per job and product) | When a job is first sprayed (spray record saved) or finished (completed/invoiced), for every product on its lines; and when a product is first added to such a job (`20261204120000`). Insert-only: the first number recorded wins. Products on jobs sprayed or finished before then are kept as "Not recorded" (NULL, not_recorded), never the product's current number; so are products of a job a spray record is moved onto before it was itself sprayed or finished. | No, once recorded: a sprayed or finished job keeps the number for that product through re-saves, remove + re-add, and a deleted and re-entered spray record. Jobs not sprayed yet record nothing and read the product's current number. No printout reads it yet: the sent spray proof (`get_job_proof_data`), applicator sheet, chemical application report and WPS notice move to it in a follow-up PR. |
| `job_chemicals` | `rei_hours`, `phi_days` | Values are copied when a product is picked on a line, when a recipe is loaded (`src/lib/recipeHelpers.ts`), or when a crop program is loaded (`src/lib/cropProgramHelpers.ts`); `save_job` saves the line. A job made from a quote leaves these values blank. Blank lines follow the product's current value at print time on any job status; filled-in lines keep their copied value. | Blank lines: yes, automatically. Filled-in lines: only if a user accepts the offer on an open job and saves. |
| `invoice_items` | `epa_registration` | When an invoice line is made. A line written without a number, saved without one on a draft or unposted invoice, or moved to another product without one, gets the product's number from the database (`20261207113000`). A posted line is never filled by an unrelated edit. | No. Posted invoices are regulated printed records. Draft lines also keep their copy (Mason, 2026-11-02). |
| `rup_sales_records` | `epa_registration`, `signal_word` | When a restricted-use pesticide sale is posted. | No. A wrong posted record needs a formal correction (void), not a silent edit. |
| Quotes and orders (`quote_items`, `order_items`) | No product label facts | They read the product's current values when needed. | Yes, automatically; there is no stored label copy. |
| WPS notice | No copy of its own | Job Detail reads `products` when printing. EPA number: the job's kept number (`job_product_epa`) once the screens PR lands. | REI/PHI: yes, automatically. EPA number: see the parent EPA correction below. |
| FieldView | No product label facts | Reads `products.rei_hours` and `products.phi_days`. | Yes, automatically. |
| Field application invoice screen | No REI/PHI or max label rate copy for its label lookups | REI/PHI and max label rate come from the product; the EPA number reloads from the `invoice_items` copy. | Product REI/PHI and max label rate: yes, automatically. Copied EPA number: no. |
| Applicator sheet and chemical application report | No stored copy of their own | Filled job line `rei_hours` / `phi_days` values print first; blank values fall back to the product. EPA number comes from the product today, from the job's kept number (`job_product_epa`) once the screens PR lands. | REI/PHI corrections reach blank lines automatically, even when completed jobs are reprinted. Filled lines change only through the open-job offer below. |
| Sent spray-job proof (`get_job_proof_data`) and customer year-end summary (`get_customer_year_end_summary`) | No copy of their own | The product's current EPA number until the screens PR, which moves them to the job's kept number and the invoice line's copy (the product's only for a line with none). | Until then, yes (as today; the correction stays switched off). After: proof only for a job not sprayed yet; year-end only for an old invoice line with no copy (a correction is refused while one exists). |
| Purchase orders (screen, PDF, email) | No copy | Read the product's current EPA number. | Yes, accepted: a purchase order is a buying request, not a compliance record. |

`product_brands` holds each brand's own registration. `product_label_drafts` holds inbound label drafts that feed products. Neither is a copy of the product label facts covered here.

The WPS notice and FieldView show the product's current REI/PHI, while the applicator sheet shows the job's filled-in copy; on a job with a kept override, these printouts differ (existing behaviour).

## Open-job offer

On the Chemicals / Charges tab of a saved `scheduled` or `in_progress` job, an office role that can edit the job (Job Detail's edit flag) sees an offer for filled-in chemical line REI/PHI values that differ from the product's current values, including inactive products. Blank job line values already follow the product and are not offered; a blank product value never clears a job value. **Update to current label** changes the form only; the normal **Save** action persists the updated `job_chemicals` lines. **Keep job values** hides the offer for that set of differences until a line or product value changes, or the page reloads. A failed lookup shows a small note.

Labels load when the set of products on the job changes, so a product correction made while the page is open shows after a reload.

New, completed, invoiced, and cancelled jobs never show this offer. Posted invoices and restricted-use pesticide sale records remain as issued because they are regulated records; any correction to those records follows the formal process.

## Parent EPA correction

Mason (2026-11-06): "yes i want to be able to fix epa issues". An admin corrects a parent's generic EPA number with a reason and evidence (`correct_product_parent_identity`, `20261207113000`). In one transaction it writes the parent and every size, and one event lists each size's before and after. It writes no job: a job not sprayed yet reads the product's number and so shows the new one, while a sprayed or finished job keeps the number `20261204120000` recorded for it (`job_product_epa`), through re-saves too. Invoices and restricted-use sale records keep the number they were made with. A spray saved at the same moment as a correction keeps whichever number was committed first.

It is refused while any invoice line for one of the sizes that has an EPA number (on an invoice not deleted) has no EPA number of its own, because that line would show the new number; the refusal names the invoices. A line for a size with no number showed none (readers fall back to the size, never the parent), so it does not block: a missing number stays correctable, and the year-end summary then shows the added number on such an old line (Mason, 2026-11-07, `docs/manual/DECISION_LOG.md`). A draft is fixed by opening and saving it; a posted one by unposting, saving and posting it again.

**Switched off** (`_product_parent_epa_correction_enabled()` returns false) until the screens that print a job's EPA number (the sent proof, Job Detail's applicator sheet, chemical application report and WPS notice) read the job's kept number and the customer year-end summary reads and groups by the invoice line's copy (it reads the product's number today); the migration that ships with those readers turns it on. Until then every printout shows the product's current number, as before.
