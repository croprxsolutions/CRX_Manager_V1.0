REQUIRES `20261107080000_product_setup_workbook` (WP-PM-11a-2) and `20261107060000_product_rate_lock` (WP-PM-11a-1); its preflight checks `apply_product_setup`, `set_product_rates`, `preview_product_rate_correction`, the rate value helpers and the idempotency helpers, so without them the one-transaction apply changes nothing.

What it does:
- Renames 11a-2's `apply_product_setup(jsonb, uuid, text)` body to `_apply_product_setup_update` (unchanged; every API-role EXECUTE revoked) and creates a new `apply_product_setup` with the same signature and grant. Setup-tab rows (no `insert` key) go to the renamed body untouched, so 11a-2's behavior, errors and retry receipts are unchanged.
- Insert mode: rows of `{insert: {...setup fields}, rates?: {rate_per_acre, rate_unit, suggested_rate}, expected_prices?}`. Admin only, actor-bound, idempotent (same `apply_product_setup` key scope, so one key cannot serve both modes), 1–2000 rows, all or nothing. Insert fields: `product_name` (required), `sku, category, vendor, manufacturer, product_form, inventory_unit, unit_size, container_unit, container_type, epa_registration, signal_word, max_label_rate_unit, use_timing` (labels, `;`-separated; `trg_sync_product_use_timings` maps them to `use_timings`), `notes, container_size, max_label_rate, rei_hours, phi_days, is_rup`. Rate, price, cost, active-status and other columns are refused (`PRODUCT_SETUP_ROW_SHAPE_INVALID`). Every `products` trigger checks each row as on the product page; a refusal names the product (`PRODUCT_SETUP_ROW_REFUSED: <name>: <check>`).
- Rates are never written by the insert: rows with `rates` get them from one `set_product_rates` call in the same transaction (key `<key>:rates`), with each row's expected values read from the row just inserted and `expected.prices` = the row's `expected_prices` from the preview. So the Lock rates switch, the unit rules and `PRODUCT_RATE_PREVIEW_CHANGED` all apply, and a refusal rolls back the whole import.
- Duplicates (`PRODUCT_SETUP_DUPLICATE`, named): a SKU any product has (case and spaces ignored), a name an active product has, or the same SKU or name twice in one request. The same EPA number under another name is allowed (another size of the same chemical). A transaction advisory lock (`crx.product_setup_insert`), taken before the retry-receipt lookup, serializes inserts so two imports cannot both pass the duplicate check and an identical retry replays the first one's receipt. It does not cover product-page inserts or Setup-tab renames; a table-wide unique SKU index is a follow-up. A note keeps its own spacing and line breaks. A row's vendor text links a vendor as the product page's insert does (`link_new_product_vendor`).
- New `preview_product_import(rows)`: admin only, 1–500 rows. For each row it runs the real insert save in a subtransaction that is always rolled back (SQLSTATE `CRXPV`); with rates it reads the after prices from `preview_product_rate_correction` and then runs the full save with them, also rolled back. Returns `{rates_locked, rows: [{row, product_name, status: ok|refused, error, after: {rate_per_acre, rate_unit, suggested_rate, tier1..3_price_per_acre}, expected_prices, sku_matches, name_matches, epa_matches, in_file_duplicate}]}`. Nothing it does is kept (sequence values aside).

Grants: `apply_product_setup` and `preview_product_import` EXECUTE to `authenticated` only (both SECURITY DEFINER, `search_path = public, pg_temp`, admin checked in the body); `_apply_product_setup_update` has no API-role EXECUTE. No table, column or existing row changes.

Per-acre prices: a new product has no tier price, so once it has a rate its tier 1–3 per-acre prices are $0.00 (`recalc_product_price_per_acre` uses tier 1 = 0); prices set later on the product reprice per acre as usual.
