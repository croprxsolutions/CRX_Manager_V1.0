## 2026-11-06 - Pushes check migration records' SQL sha256 pins

On PR #1579 a migration record's `SQL sha256` pin was hashed from the Windows CRLF working copy instead of the LF text git stores, and four CI checks failed. `npm run check:docs` already caught it but was not run before the push. `.husky/pre-push` now asks `scripts/prepush-needs-build.mjs --pins` whether the push changes a migration `.sql`, a `docs/reference/migrations.d/` record or `migration-history.md`; only then does it extract those files from each pushed commit and run `node scripts/check-doc-drift.mjs --pins-only <dir>` (about 1 second), which runs just that one check. A wrong pin blocks the push and prints how to compute the LF hash. Proof: a throwaway commit pinned to the CRLF hash was refused by the real hook; the same commit pinned to the LF hash (`git show <sha>:<file> | sha256sum`) passed. Tests: `scripts/check-doc-drift.test.mjs`, `scripts/prepush-needs-build.test.mjs`.
