**Words used here.** The Stage 2 sheet's words (parent, size, copied value, pass, harness, retry key) mean the same. Also:
- *Ingredient*: one row in `active_ingredients`, which is always one **specific chemical form** (for example glyphosate isopropylamine salt, or S-metolachlor). A form may name a *canonical parent* (glyphosate acid) and, only where the chemistry allows, a *canonical fraction* (0.741) (D-A).
- *Basis*: what a strength number measures: the form itself (`active_ingredient`) or its acid (`acid_equivalent`); for fertilizer, `oxide` (P₂O₅, K₂O) or `elemental` (P, K).
- *Chemistry*: a parent's ingredient rows, mode-of-action rows and fertilizer analysis rows, all under one `chemistry_version`.
- *Usable EPA number*: a number that is not blank after trimming (grand plan D-Z).

## 3. What DM-1 stores, and the rules it enforces

**Ingredient identity (D-AA, D-A).**
- `active_ingredients` holds one row per specific chemical form: display `name` (never renamed by any resolve, D-AA-4), `name_key` (lower, trimmed, inner spaces collapsed), `cas` (nullable; format and check digit validated in the database; unique across **all** rows, active or retired, so one chemical never gets a second ID), `canonical_ingredient_id` (nullable self-reference to the parent acid or element), `canonical_fraction` (nullable, finite, `0 < f ≤ 1`), `fraction_basis` (`acid_equivalent` only, required exactly when a fraction is present; elemental conversion is the fertilizer table's fixed oxide factors, never an ingredient fraction; a fraction also requires `canonical_ingredient_id`, by `CHECK`), `is_parent_form boolean NOT NULL DEFAULT false` (the row **is** the acid others are measured as; `CHECK`: true only with no canonical parent and no fraction). A named canonical parent must be an **active row with `is_parent_form = true`**, checked by every writer under the ingredient-list lock, so no two forms can name each other. `status` (`active` or `retired`), `retire_reason`, `row_version`, who and when.
- **Resolving an ingredient** (every writer, one private helper `_resolve_active_ingredient`): an entry with a CAS uses the active row with that CAS (automatic, D-AA-1), or creates one. A CAS that belongs to a **retired** row is refused by name (`INGREDIENT_RETIRED: <name> was retired; reactivate it`), never re-created. If the entry also states a canonical parent, fraction, basis or `is_parent_form` that differs from the matched row's, it is refused before any write (`INGREDIENT_FRACTION_CONFLICT`, same as D-AA-3). The admin corrects the ingredient instead. An entry with only a name creates a new **provisional** row (no CAS); if any active row shares its `name_key`, it appears on the possible-duplicates list (D-AA-2). It is never joined to that row. An entry that matches an existing row by CAS or name but names a **different canonical parent** is refused before any write (`INGREDIENT_PARENT_CONFLICT`, D-AA-3: Mason's settled rule that ambiguous chemistry never enters, on every path). An entry may also name an existing ingredient by ID (the screen's picker), which is not a claim and needs no review.
- **Duplicates are replaced, never linked (Mason, 2026-11-06).** There is no merge, alias or `merged_into_id`; every ingredient ID in every row means exactly that ingredient. A duplicate is fixed in two ordinary steps, each reviewed and each undoable (a swap by another correction; a retirement by `reactivate_active_ingredient`):
  1. **Swap it out, parent by parent.** On each parent using the duplicate, `correct_parent_chemistry` swaps the row to the right ingredient, with reason and evidence. **The swap copies nothing (Mason, 2026-11-07, answering Sol's landing-round HIGH "a swap to an unrelated ingredient inherits false chemistry"; `20261211100000`):** the request states the new row's strength, unit, basis and source, and lists which of the old row's modes of action stay (`modes_of_action`, `[]` for none; each must be one of the old row's, so nothing new enters this way). The screen pre-fills both from the old row and the admin confirms or edits them, so a correct duplicate swap is one click and a wrong-chemical swap never inherits values silently. The preview shows old and new values for every size. If the parent already has the right ingredient, a plain swap is refused (`INGREDIENT_ALREADY_ON_PARENT`); the admin uses **consolidate** in the same correction instead: the preview shows both rows side by side, the admin states the kept row's final strength, basis and source, and lists which of the duplicate row's modes of action move to the kept ingredient (pre-filled with all of them; one already there is not doubled).
  On a parent the EPA gate refuses, no typed swap or value change is possible (D-Z). The one correction allowed there is **retiring a typed row** (refused, `CHEMISTRY_EPA_ROW_KEPT`, while the EPA lookup has confirmed one of its modes of action; mode-of-action rows record `source` typed or epa_lookup), with reason and evidence, so a duplicate left over from before the number (or one the EPA auto-fill has since supplied correctly) can always be removed; nothing typed is added or changed. Until then it stays listed as "waiting on the EPA auto-fill".
  2. **Retire the unused duplicate.** `retire_active_ingredient` needs a reason. It is refused (`INGREDIENT_IN_USE`, naming the parents and forms) while any active parent row or mode-of-action row uses it, or while any active form names it as canonical parent.
- **A CAS added later that already belongs to another ingredient** is refused (`INGREDIENT_CAS_TAKEN: this CAS belongs to <name>; swap this ingredient to <name> on its products, then retire it`). CAS stays unique across all rows, and nothing is joined automatically.
- **Possible duplicates (D-AA-2, Mason's side-by-side review)** is computed, not stored: each active provisional ingredient beside every other active ingredient with the same `name_key`, with the parents using each. Mason resolves a real duplicate with the two steps above. A same-name pair that is really two chemicals stays listed until each gets its CAS (D-AA-2: a name alone never settles identity).
- **Fraction edits** on an ingredient that any parent uses change cost for every such parent, so changing an established `canonical_ingredient_id`, `canonical_fraction`, `fraction_basis`, `is_parent_form` or `cas` needs a reason and evidence; filling a blank one also needs them once any parent uses the ingredient (it creates new cost figures there), and needs neither on an unused ingredient. Every ingredient edit is checked against the **final state of everything that depends on it**, in the database, before it saves: clearing `is_parent_form` is refused while any active form names the row as canonical parent, and clearing a form's canonical parent (or turning off `is_parent_form`) is refused while any active parent row stores an `acid_equivalent` strength on that form (`INGREDIENT_IN_USE`, naming them). Any edit that sets or changes one of those fields, **filling a blank included**, is refused while any parent using the ingredient is refused by the EPA gate (`CHEMISTRY_FROM_EPA_ONLY`), so a global edit never changes EPA-sourced chemistry behind the gate; DM-4 decides how EPA data updates identity. The preview returns a fingerprint (a hash over the requested field changes in a fixed canonical form, and the sorted IDs and `row_version`s of every active parent row using the ingredient **or any form that names it as canonical parent**, the sorted member size IDs of each of those parents, every form naming it as canonical parent, and the ingredient itself); the save takes the ingredient-list lock (which every chemistry writer also takes), recomputes that fingerprint and refuses with `INGREDIENT_USAGE_CHANGED` if it differs, so no parent's cost changes without having been shown. Every change appends to `active_ingredient_events`.
- **"Needs CAS" worklist**: every active provisional ingredient, with the parents using it (`get_active_ingredient_worklist`). Retyping a name already on the list instead of picking it creates another provisional row, which shows up as a possible duplicate (D-AA-2 allows no name-only identity); the screen's picker offers the existing name first to keep that rare.
- **Acid-equivalent strength needs a canonical parent.** A strength stated on the `acid_equivalent` basis is refused unless the form names a canonical parent (the acid it is measured as), or the form is itself the acid (`is_parent_form = true`). A form with neither, such as a salt entered without its acid, is refused on that basis.

**A parent's chemistry** (all rows keyed to the parent; `retired` rows keep their history and are excluded from every live read and from cost):
- `product_parent_ingredients`: `id`, `parent_id`, `ingredient_id` (the specific form), `strength_value numeric` (finite and > 0; at most 100 for `pct_ww` and at most 20 for `lb_per_gal`; NULL exactly when `strength_unknown`), `strength_unknown boolean`, `strength_unit` (`pct_ww` or `lb_per_gal`), `strength_basis` (`active_ingredient` or `acid_equivalent`), `source` (`label`, `sds`, `supplier`, `other`, and `epa_lookup` for DM-4's writer only), `source_note`, `status`, `row_version`, who and when. One active row per (parent, ingredient). (The mode-of-action and fertilizer tables carry `row_version` too.) `lb_per_gal` is refused on a dry parent. Every writer also checks the parent's final state: the mass of each active row's own chemical form, added up, may not exceed 100% w/w (or the 20 lb/gal cap for `lb_per_gal` rows) (`CHEMISTRY_TOTAL_IMPOSSIBLE`). An `active_ingredient` row counts at its value; an `acid_equivalent` row counts at value ÷ fraction (at its value when the form is the acid itself); an `acid_equivalent` row with no fraction counts at its value, a lower bound because a fraction is never above 1, and an unknown strength counts as 0. This is a **sanity check that refuses what the known numbers already prove impossible**; it cannot prove a product possible while a fraction or strength is unknown, and the plan does not claim it does. Fertilizer rows are checked the same way on one basis: each row is turned into its elemental percent (oxide rows by the fixed factors in section 4) and the elemental percents together may not exceed 100 (`CHEMISTRY_TOTAL_IMPOSSIBLE`); they are not added to the ingredient rows, which may describe the same mass. Zero strength is refused (an ingredient at 0 is not an ingredient); unknown is its own state. % w/v is not stored: the entry asks for the label's lb/gal, which US labels state (a % w/v-only label is entered as unknown strength with the note).
- `product_parent_modes_of_action`: `parent_id`, `ingredient_id`, `scheme` (`HRAC`, `FRAC`, `IRAC`), `group_code` (trimmed text, ≤ 10), `status`, who and when created and last changed; unique on the four (active rows). The ingredient must be an active ingredient row of the same parent.
- `product_parent_fertilizer_analysis`: `parent_id`, `nutrient` (fixed list: N, P, K, S, Ca, Mg, B, Cl, Co, Cu, Fe, Mn, Mo, Ni, Zn), `basis` (`oxide` allowed only for P and K; otherwise `elemental`), `percent numeric` (% w/w, finite, > 0 and ≤ 100) or `unknown`, `source`, `source_note`, `status`, who and when created and last changed; one active row per (parent, nutrient), whatever the basis, so P is never entered both as P₂O₅ and as P. A label's P₂O₅ is stored as P on the `oxide` basis; it is never silently converted on save.
- **Biologicals** store no CFU count (Mason, 2026-10-29): there is no CFU column. Any other registered active a biological carries is an ordinary ingredient row, with strength unknown where the label gives none.
- `product_parent_chemistry_state(parent_id PK, chemistry_version bigint, updated_by, updated_at)`: created on a parent's first chemistry write (version 0 means "no chemistry yet"). Every chemistry write, correction and (later) proposal is bound to it.
- `product_chemistry_events`: append-only (update, delete and truncate refused, like `product_parent_events`): `parent_id`, `event_type` (`set`, `corrected`), `chemistry_version` after, `reason`, `evidence`, `before_values`, `after_values`, who and when.

**Add versus correct (DECISION_LOG 2026-10-30 correction rule, as PAR-1's identity correction).** `set_parent_chemistry` may only **add** a row (ingredient, mode of action, nutrient) or **fill** a strength or percent that is unknown. Changing an established strength, unit or basis, changing a source, retiring a row, or swapping one ingredient for another is refused there (`CHEMISTRY_CHANGE_NEEDS_CORRECTION`) and goes through `correct_parent_chemistry` with reason and evidence after its preview shows old and new values and every size of the parent.

**EPA gate (D-Z, per registration), one shared helper.** `_parent_chemistry_epa_refusal(p_parent_id) RETURNS text` returns NULL when the parent may take typed chemistry, or a named refusal listing each usable number found on: the parent's generic number, any member size's `epa_registration`, any active parent brand, and any legacy `product_brands` row of a member size. **In DM-1 it refuses whenever any usable number exists** (`CHEMISTRY_FROM_EPA_ONLY: this product has EPA number(s) …; its chemistry comes from the EPA auto-fill`). Both `set_parent_chemistry` and `correct_parent_chemistry` call it (Stage 2 sheet 7.8, round-8 MED: one gate in one helper), and DM-1b's workbook path calls the same helper later. The gate guards **typed** chemistry only. DM-4's commit of a **successful** EPA lookup is the path the gate points to, so it does not call the gate: it calls `_apply_parent_chemistry` directly, bound to its reviewed proposal, after the same lock order. Rows it writes carry `source = 'epa_lookup'`, a value only that private path can set (public RPCs refuse it). It **never changes or retires a typed row** (D-L): where a lookup value differs from an existing typed row on that parent, `_apply_parent_chemistry` refuses that change by name (`CHEMISTRY_TYPED_ROW_KEPT`) and DM-4 routes it to review; how that review resolves is DM-4's to define. **The failed-lookup exception is DM-4's**: DM-4 re-issues this helper to let a number through only when its failure row carries the lookup ID, the registration version from REG-1 and the parent link it was bound to, with no later success or open proposal for that number (7.8, "DM-1 / DM-1b" row). DM-1 creates no failure table. Chemistry already stored when a parent later gains a number (a new brand, or the 7.7 correction) stays live and readable (D-L: typed chemistry is never overwritten); further typed changes are refused until the number is cleared or DM-4 supplies them.

**Serialising the gate with brand and number writers.** Every chemistry writer (and `set_parent_cost_reference`) locks in this order: the parent row `FOR UPDATE` (round-3 review, 2026-11-07: it also blocks a concurrent foreign-key insert of a brand or size on that parent, so the gate holds even against a writer that takes no lock of its own); then its member `products` rows `FOR SHARE` in product-ID order; then the chemistry state row, created if missing with `INSERT … ON CONFLICT (parent_id) DO NOTHING` (version 0) and then locked with `SELECT … FOR UPDATE`, so two concurrent first writes serialise and the second gets `CHEMISTRY_STALE`, never a raw duplicate-key error; then the ingredient-list advisory lock (`pg_advisory_xact_lock(hashtext('crx.active_ingredients'))`). It evaluates the gate only after those locks.
- The parent lock `FOR UPDATE` conflicts with the `FOR SHARE` that `upsert_parent_brand` takes on the parent (`20261123120000:1157`), so a parent brand is serialised even on a parent with no sizes (a parent can be left with none, because moving its last size away is allowed).
- The member `FOR SHARE` conflicts with the `FOR NO KEY UPDATE` that the legacy `upsert_product_brand` takes on the size row (`:1329-1331`) and with every PAR-1 parent writer's `FOR UPDATE`.
- So a number added concurrently either commits first (and the gate sees it) or waits for the chemistry write.
- **No deadlock cycle.** PAR-1 parent writers and `upsert_parent_brand` take the parent first, then members in ID order, the same order as here. `upsert_product_brand` and PAR-2's group approval lock only product rows and never lock an existing parent's row afterwards, so they cannot hold a size while waiting for a parent this writer holds.
- **No size can join a parent behind the gate's back.** PAR-2's group approval only ever inserts a **new** parent and puts the sizes there (`_approve_product_parent_group`, `20261123120000:1059-1074`), so it never adds a size to a parent a chemistry writer is checking. PAR-1's `add_product_size` and `move_product_size` lock the target parent `FOR UPDATE`, which waits for this writer's `FOR UPDATE`.
- An ingredient edit that sets or changes an identity field (CAS, canonical parent, fraction, basis or `is_parent_form`, blank or established) first locks every parent using the ingredient, directly or through a form that names it as canonical parent, in the section 3 order (parents `FOR UPDATE` in parent-ID order, then their members `FOR SHARE`), then takes the ingredient-list lock, then recomputes the usage fingerprint and the EPA gate for each of those parents (the same direct-or-through-a-form set), and on save bumps each of those parents' `chemistry_version` with a `corrected` event naming the ingredient change, so a cost read's version always changes when its figures can, so a brand number added concurrently either commits first (edit refused) or waits. A chemistry writer holds at most one parent before the list lock and edits take parents in ID order, so no cycle forms.
- Other ingredient writers (creating, `retire_active_ingredient`, `reactivate_active_ingredient`; none can change a figure on a parent) take only the ingredient-list lock, which every chemistry writer takes last. Because of that, and because inserts run in sorted (CAS, then name key) order inside one transaction, they cannot deadlock against a chemistry writer. That also satisfies D-AA-4's "deterministic order".

**Reads.** With no aliases, a direct table read and an RPC read show the same IDs. The screens still read through the RPCs, because those carry names, refusal reasons and the active-user check. Chemistry is not cost: `get_parent_chemistry(p_parent_id)` and `search_active_ingredients(p_text)` are open to active users (no key; no cost or price). Cost is admin-only in the database (below).

**Saved records.** No saved quote, order, job, blend ticket, invoice or document stores or prints chemistry today, and DM-1 adds none; cost per lb of active is a live admin view. So a correction cannot rewrite history. Any later package that prints ingredient amounts on a saved record must snapshot them there (unchanged from the outline).

## 4. CMP-1 · cost per lb of active

**One figure per active ingredient and basis, per generic** (DECISION_LOG 2026-10-28 Q4, 2026-10-15, 2026-10-22). A premix has one figure for each active, each costed against the whole product's price; pounds of unlike actives are never added.

**Reference size.** The parent's figures are its reference size's. The reference is the parent's **active** `bulk` member when it has one. Otherwise it is the size an admin picks in `product_parent_cost_reference(parent_id PK, reference_product_id, row_version, set_by, set_at)` through `set_parent_cost_reference`:
- admin only, with a retry key and expected version;
- uses the section 3 lock order;
- refused while the parent has an active bulk member, since an active bulk size always wins;
- an inactive bulk size does not block picking. The parent figure is refused by name while the reference is unset, inactive or no longer a member (a move or deactivation clears nothing; the figure stops until an admin picks again). Every size's own figure is listed beneath as detail; sizes are never averaged.

**The math** (one private function, `_parent_active_cost_rows(p_parent_id)`; exact `numeric` throughout; one rounding, half-up to whole cents, on each final figure; no intermediate rounding):
1. **Cost per gallon or per lb.** `current_cost` is dollars per the size's `inventory_unit`. A liquid size: `cost_per_gal = current_cost × 128 ÷ liquid_oz(inventory_unit)`. A dry size: `cost_per_lb = current_cost × 16 ÷ dry_oz(inventory_unit)`. `liquid_oz` and `dry_oz` come from one new private helper `_unit_factor_oz(p_unit, p_unit_type)` with BLK-1a's rule (case-insensitive, that `unit_type`, `0 < factor < ∞`, NULL when spellings disagree). A count unit (`Ea`, `Unit`), an unknown unit, or a cost that is missing, zero, negative, non-finite or not whole cents (`current_cost` is a legacy numeric-dollar column, so it is checked on read and never rounded into shape; the live table already enforces it with `products_current_cost_cent_scale_chk` (whole cents, finite) and `chk_product_cost` (zero or more), read from the catalog on 2026-11-06; the preflight confirms both are present and validated, and the read-time check stays as the second guard, for `NaN`), or a `seed` / `each` parent is refused by name per size. Sizes priced in metric units (`g`, `MG`) are also refused by name (`UNIT_NOT_SUPPORTED`). No active size is priced per `g`, and the `unit_conversions` gram factor is truncated (0.03527396 oz), which can move the final cent. The two `MG` sizes wait on Mason's question 2. If they are really another unit, fixing the unit puts them on the normal path. If they really are milligrams, a later change adds metric with exact factors (1 g = 1/453.59237 lb). *shortcut: count-unit sizes are refused because none is active today; a count unit would need a net weight per unit, which no package defines yet, so that is a new interface to add when one appears.*
2. **Pounds of active per gallon or per lb.**
   - Liquid, `lb_per_gal`: the stated value.
   - Liquid, `pct_ww`: `value ÷ 100 × lb_per_gal`, where `lb_per_gal` is the parent's **approved** weight per gallon from DM-2 (interface below). None approved: refused (`DENSITY_NOT_APPROVED`).
   - Dry, `pct_ww`: `value ÷ 100`.
   - Fertilizer analysis: the same, with the row's percent (always % w/w).
   - Unknown strength or percent: refused for that row.
3. **Cost per lb of active** = step 1 ÷ step 2, per row, on the row's own basis.
4. **Conversions** (one function, `_chemistry_convert(p_value, p_from_basis, p_ingredient_id or p_nutrient)`, returning either a number or a refusal reason, never a bare nullable; Stage 2 / August R-4a): an `active_ingredient` strength also yields an `acid_equivalent` figure when its form has `fraction_basis = 'acid_equivalent'` and a fraction (`lb_ae = lb_ai × fraction`), or when the form **is** the acid (`is_parent_form = true`; then the ae figure equals the ai figure by that explicit flag, never by a missing fraction); a fertilizer `oxide` row also yields an `elemental` figure with fixed factors written in the migration as exact atomic-weight ratios, not rounded decimals: **P₂O₅ → P = (2 × 30.973762) ÷ (2 × 30.973762 + 5 × 15.999)** (about 0.43642) and **K₂O → K = (2 × 39.0983) ÷ (2 × 39.0983 + 15.999)** (about 0.83015). Like everything else, they round only at the final cent. Never the reverse; never across forms; an isomer (S-metolachlor) is its own ingredient by CAS, and a NULL fraction refuses any numeric conversion. A refusal is returned as that figure's reason; no `COALESCE(fraction, 1)` exists anywhere (a mutation case proves it).

**RPC.** `get_parent_active_costs(p_parent_id)`: `SECURITY DEFINER`, admin-only (`ADMIN_REQUIRED` before any read; a non-admin receives nothing), read-only, no key. Returns the reference size, the parent figures, and per size: priced unit, cost per gal or lb, and per row its figure in cents or its refusal reason, plus the converted figures. Every figure is labelled "from catalog cost" and carries the approved weight-per-gallon row ID it used. Guards on the read:
- **One snapshot.** The RPC and `_parent_active_cost_rows` are `STABLE`, so every read inside them sees one database snapshot; the reply carries the `chemistry_version` it used.
- **Unit fit per size.** Each row is checked against each size's own unit type at read time: a `lb_per_gal` row on a dry size is refused (`STRENGTH_UNIT_MISMATCH`), so a parent later switched from liquid to dry by a PAR-1 writer can never produce a figure from the wrong unit.
- **Strength within the product's weight.** On a liquid size, when an approved weight per gallon exists, the form mass of all the parent's ingredient rows together (`lb_per_gal` rows at their value, `pct_ww` rows at value ÷ 100 × that weight, each counted as in section 3, lower bounds included) may not exceed it; otherwise every figure of that parent, fertilizer rows included, is refused (`STRENGTH_EXCEEDS_DENSITY`). This is checked at read time because the weight may be approved only after the chemistry is entered.
- **Density contract.** The weight from `_approved_parent_lb_per_gal` is used only when it is finite, greater than 0, at most 20, and comes with its row ID; anything else is refused (`DENSITY_INVALID`), whatever DM-2 returns.
- **Exact at any size.** Cents are returned as whole-number strings, never floating-point numbers, and the screen shows them as text, so a very large figure (a tiny strength) is shown exactly rather than capped or rounded.

**DM-2 interface (defined here; DM-2 provides the body).** One private function, no grants:
`_approved_parent_lb_per_gal(p_parent_id uuid, OUT lb_per_gal numeric, OUT weight_row_id uuid)`, `STABLE SECURITY DEFINER SET search_path = public, pg_temp`, owned by `postgres`: with `REVOKE ALL … FROM PUBLIC, anon, authenticated, service_role` stated by whichever migration creates it and repeated by DM-2's replacement, so no caller can run it directly. It returns the parent's one **approved** weight per gallon and its row ID, or NULL for both when there is none (a draft never counts). Whichever of DM-1 and DM-2 applies first creates it: DM-1's migration creates it only when `to_regprocedure` finds none; if one exists, DM-1's preflight checks its contract (the OUT columns and types, `STABLE`, `SECURITY DEFINER` with `search_path = public, pg_temp`, owner `postgres`, no `EXECUTE` for `PUBLIC`, `anon`, `authenticated` or `service_role`) and stops if any differs. The stub has a body returning NULL (so every % w/w liquid figure refuses with `DENSITY_NOT_APPROVED` until DM-2); DM-2's migration `CREATE OR REPLACE`s it with the real body and keeps the signature. The DM-1 harness proves the stub, its replacement by a stand-in, and the preflight stopping on a wrong-shaped stand-in. Running the **real** DM-1 and DM-2 migrations in both orders is owed by whichever database PR is built second, and is not claimed here. DM-2's sheet adopts this name and signature, or both sheets are changed together before either database PR is built. A note for the DM-2 session is left in the shared notes folder.

- `set_parent_chemistry(p_parent_id, p_expected_chemistry_version, p_changes jsonb, p_idempotency_key)`: adds rows and fills unknown values only (section 3), all-or-nothing for one parent. It takes no reason: adding or filling a blank needs none, the same as PAR-1's first rate entry. The outline's `p_rows` is renamed `p_changes`, because the call also carries mode-of-action and fertilizer entries. `p_changes` is a list of `{kind: ingredient | mode_of_action | fertilizer, …}` entries; an ingredient entry names `ingredient_id`, or `{ref, name, cas, is_parent_form, canonical_ingredient_id, canonical_fraction, fraction_basis}` for a new form, where `ref` is a short label the screen makes up (unique within the call; a repeated `ref`, or an `ingredient_ref` naming none, is refused before any write) so a mode-of-action entry in the same call can name `ingredient_ref` instead of an ID it cannot know yet. All entries are checked against the final state in one transaction; two entries touching the same row are refused (`CHEMISTRY_DUPLICATE_CHANGE`). Runs the lock order and the EPA gate, then writes one `set` event and bumps the version. Refuses an inactive parent and an empty change.
- `preview_parent_chemistry_correction(p_parent_id, p_changes jsonb)` (admin, read-only): old and new values per row, every size of the parent, the gate's result, the current version, and a preview fingerprint (a hash over the requested changes in a fixed canonical form, the chemistry version, the parent's `parent_version` (so an EPA change since the preview voids it), the sorted member size IDs, and the `row_version` of every ingredient the changes touch), so the save must send exactly the changes that were previewed. A refused preview returns no fingerprint, so it cannot authorize a save.
- `correct_parent_chemistry(p_parent_id, p_expected_chemistry_version, p_expected_preview_fingerprint text, p_changes jsonb, p_reason, p_evidence, p_idempotency_key)`: recomputes the preview fingerprint under its locks and refuses `CHEMISTRY_PREVIEW_CHANGED` if a size joined or left or a touched ingredient changed since the preview; changes, retires, swaps or consolidates rows; retiring an ingredient row also retires its mode-of-action rows, and swapping one carries them to the new ingredient (refused with `INGREDIENT_ALREADY_ON_PARENT` when the new ingredient is already on the parent), all shown in the preview; reason and evidence required; same locks and gate, except that retiring a typed row is allowed on an EPA-gated parent (section 3); on an **inactive** parent it allows only swaps, consolidations and retirements (so duplicates can always be cleaned up), never new or changed values; one `corrected` event.
- `preview_active_ingredient_change(p_ingredient_id, p_fields jsonb)` (admin only, `ADMIN_REQUIRED` before any read, like the chemistry correction preview) and `save_active_ingredient(p_ingredient_id, p_expected_row_version, p_expected_usage_fingerprint text, p_fields jsonb, p_reason, p_evidence, p_idempotency_key)`: creates an ingredient (`p_ingredient_id` NULL, through the same `_resolve_active_ingredient`, so a create naming an existing CAS returns that ingredient with `reused: true` and writes nothing new) or edits one; reason and evidence required to change an established CAS, canonical parent, fraction, basis or `is_parent_form`; an **edit** adding a CAS already on another row is refused (`INGREDIENT_CAS_TAKEN`); never renames another row.
- `retire_active_ingredient(p_ingredient_id, p_expected_row_version, p_reason, p_idempotency_key)`: retires an unused ingredient. It is refused while any active parent row or mode-of-action row uses it, or any active form names it as canonical parent (`INGREDIENT_IN_USE`, naming them). A retired ingredient cannot be picked or resolved.

- `set_parent_cost_reference(p_parent_id, p_reference_product_id, p_expected_row_version, p_idempotency_key)`: the size must be an active member; refused while the parent has an **active** bulk member. `p_reference_product_id` NULL clears the reference (always allowed, even on a parent with no sizes left), so a reference left behind by a move can always be removed.

A retired row is excluded from reads and cost and kept with its history.
- **Identity (D-AA, replace):**
  - Two writes naming one CAS under two names resolve to one ingredient.
  - Two name-only entries with one normalized name create two provisional ingredients listed as possible duplicates; nothing is joined.
  - A name or CAS match claiming a different canonical parent is refused with zero writes.
  - Adding a CAS that belongs to another active ingredient is refused (`INGREDIENT_CAS_TAKEN`).
  - Swapping a duplicate on a parent carries its mode-of-action rows; swapping onto a parent that already has the target is refused.
  - Retiring an ingredient still used by a parent row, a mode-of-action row or a form's canonical parent is refused; retiring it once unused succeeds, and it can no longer be picked.
  - No resolve renames a row. Two concurrent first-time entries of one new CAS create one ingredient.
- **Astra round (2026-11-06):** clearing `is_parent_form` on an acid that a salt names, or a salt's canonical parent while an `acid_equivalent` row uses it, is refused; a correction previewed before a size joined the parent is refused (`CHEMISTRY_PREVIEW_CHANGED`); consolidating keeps every mode-of-action entry; a retired ingredient is reactivated and its CAS re-resolves to it; a create naming an existing CAS returns that ingredient; two 60% actives on one parent are refused; a `lb_per_gal` row on a size that is now dry is refused; a stand-in weight of 0 or NaN gives `DENSITY_INVALID`; a figure above $1,000,000 per lb comes back as an exact string; a new ingredient and its mode of action saved in one call via `ref`; a swap on an inactive parent succeeds while an add is refused.

- **Units:** sizes priced per `g` or `MG` are refused with `UNIT_NOT_SUPPORTED`; a count-unit size is refused by name.
- **Private helper:** `_approved_parent_lb_per_gal` cannot be executed by `anon`, `authenticated` or `service_role` (read back from the catalog after both the stub and the replacement).
- **Oxide factor:** a 100% P₂O₅ product priced at $100/lb gives the figure from the exact ratio (hand-checked in the proof), not from 0.4364.

- **Concurrency:**
  - Two concurrent first chemistry writes on one parent: one succeeds, the other gets `CHEMISTRY_STALE`, never a duplicate-key error.
  - A parent brand number added concurrently on a parent with no sizes: either the brand commits first and the chemistry write is refused, or the chemistry write succeeds and then the brand saves.
  - An `acid_equivalent` strength on a form with no canonical parent that is not marked as the acid is refused.
  - An inactive bulk size lets an admin pick the reference.
- **Every writer:** a non-admin call writes nothing; a direct insert, update or delete on every new table is refused; a NULL key is refused; one key twice writes once; one key with a changed request is refused; a stale `chemistry_version` or `row_version` is refused by name.

## 8. Risks
