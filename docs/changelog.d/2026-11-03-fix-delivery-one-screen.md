## 2026-11-03 — Fix Delivery from one screen, and Return Product (local candidate)

Local candidate migration `20261106100000_fix_delivery_one_screen.sql` adds admin-only `preview_fix_delivery()` and `fix_delivery()`. When a completed delivery was entered wrong (amount or product), one admin action voids or cancels that delivery's own unpaid invoice and voids the delivery in one transaction: stock comes back once, the order lines reopen, prepay returns to the customer's credit, and the order's pending commission is re-created as pending (the invoice void cancels it and cancelled commissions cannot reopen). The screen then opens New Delivery for the same order. It refuses an applied payment, a split-group or whole-order invoice, a closed month, a return, billing outside CRX, or a commission already in a payout, and it refuses if anything it showed (an invoice, its status or amount, an order draft, an item) changed since the preview. The month-end summary and bottom-line P&L now skip cancelled commissions, so the fixed order's cancelled original is not counted next to its pending copy. Mason's decision of 2026-11-03 (shared vault). The delivery page also gains **Return Product**, which opens Returns pre-filled, and the Void Delivery window no longer says posted invoices are "manually reviewed" (they block the void). Proof: `scripts/smoke/prove-fix-delivery-real-schema.mjs`.
