## 2026-11-03 — Fix Delivery database functions (local candidate)

Local candidate migration `20261106150000_fix_delivery_one_screen.sql` adds admin-only `preview_fix_delivery()` and `fix_delivery()`. When a completed delivery was entered wrong (amount or product), one admin action voids or cancels that delivery's own unpaid invoice and voids the delivery in one transaction: stock comes back once, the order lines reopen, prepay returns to the customer's credit, and the order's pending commission is re-created as pending (the invoice void cancels it and cancelled commissions cannot reopen). It refuses a cancelled or voided order, an applied payment, a split-group invoice (on the delivery or a draft on its order) or whole-order invoice, a closed month, a return, billing outside CRX, or a commission already in a payout, and it refuses if anything it showed (the delivery's number or completion date, the order it belongs to or its status, an invoice, its status, date or amount, an order draft, an item) changed since the preview. The month-end summary and bottom-line P&L now skip a cancelled commission only when a row replaced it (Fix Delivery's re-created copy names its original in the new `commissions.replaces_commission_id` column, so a later edit or void of the copy cannot make the original count again; a trigger lets only Fix Delivery set that link), so the fixed order's original is not counted twice and an ordinary invoice void leaves past months' totals unchanged. Mason's decision of 2026-11-03. The screen ships separately in PR #1421, after this migration is live. Proof: `scripts/smoke/prove-fix-delivery-real-schema.mjs`.
