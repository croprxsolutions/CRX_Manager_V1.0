What it does:
- A seed or each parent's one rate is per stock unit (PAR-1 previews and saves it in each size's `inventory_unit`). A parent holding a 50 Lb bag and a size stocked as Unit would give 30 Lb/acre to one and 30 Unit/acre to the other. Adding a size (`add_product_size`, through `_insert_parent_size`) and moving one (`preview_move_product_size` and `move_product_size`, through `_product_size_move_refusal`) now refuse a size whose stock unit differs from the parent's other sizes, ignoring case and spaces: `PRODUCT_PARENT_UNIT_MISMATCH: every size of "<parent>" is stocked in <unit>; a seed or each parent's rate is per stock unit`. Liquid and dry parents are unchanged; their rate unit converts.
- New private `_product_parent_unit_refusal(product_parents, text, uuid)` (SECURITY DEFINER, `search_path = public, pg_temp`, no API-role EXECUTE). Re-issued private `_insert_parent_size` and `_product_size_move_refusal` (same signatures, grants re-asserted, postflight checks them).
- Private `_apply_parent_rates` re-issued (same signature and grants, from the CodeRabbit review of PR #1501): when `set_parent_rates` sends a parent whose rates and sizes already match, that parent is skipped (no event, no version change) instead of refusing the whole upload; `correct_parent_rates` still refuses an unchanged correction with `PRODUCT_RATE_CORRECTION_NO_CHANGE`. A seed or each rate sent with a unit other than the sizes' stock unit (ignoring case and spaces) is now refused with `PRODUCT_RATE_UNIT_MISMATCH` instead of being saved in the stock unit (Sol HIGH, 2026-11-05); a blank unit still means the stock unit.
- `move_product_size` (public, from the CodeRabbit review of PR #1501) re-issued with the same signature and grants (EXECUTE to `authenticated` only, postflight checks it): a moved size now stores the new parent's normalized EPA number whenever the parent has one, as an added size does. Before, a size typed `100 - 1` kept that spelling under a `100-1` parent; the move refusal already requires the size's normalized number to be absent or the parent's.

No table or row changes, and no grant on an existing object. Live had no parents when this was written (read-only count, 2026-11-05).
