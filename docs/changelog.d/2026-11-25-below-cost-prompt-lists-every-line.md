## 2026-11-25 — The below-cost approval prompt lists every below-cost line in a save (pricing audit fix 1)

- New migration `20270307100000_below_cost_prompt_lists_every_line.sql` (not applied live; record in `docs/reference/migrations.d/`). Re-creates `_enforce_below_cost_line` from `20270201180000` and adds `_raise_below_cost_reason_list` with a deferred constraint trigger on order, quote and invoice lines.
- When an admin saves a quote, order or invoice with lines below today's cost and no reason yet, the save no longer stops at the first such line. It runs to the end and is refused once at commit, and the prompt lists every below-cost line (product, price, cost, quantity, shortfall) with the save's total shortfall. Nothing is saved until the admin gives a reason, as before; the retry logs one approval per line, as before. A kept invoice line that `save_invoice` re-inserts and then restores to its saved id keeps its place in the list, so re-saving a draft with an approved below-cost line still asks, as before (found by the security review; proof case 12). An invoice line billing an order line priced in the same save at the same price (pricing a delivered rush order) is the same sale, so it is listed and counted once. Sales reps, the reason transport and the approval log are unchanged.
- Screen: `BelowCostApprovalModal` shows the list and total when the database sends it, and today's first-line text when it does not (older database). Each prompt now starts with an empty reason (a reason typed for one save no longer carries into the next save's prompt), and the reason box takes at most 1,000 characters, what the approval log keeps.
