**Stale imported skills.** `node scripts/sync-agent-workflows.mjs --archive-imported` previews, and `--confirm` moves, the Codex importer's `.agents/skills/source-command-*` folders from the checkout you run it in to `.git/crx-archive/imported-skills/<time>/`. Every file is hashed against its source, every folder (empty ones included) is recreated and listed, and `restore-map.json` is saved before anything leaves the active folder; a folder that gains or loses a subfolder meanwhile stays in place. The original folder is then renamed into `originals/<name>` in the same archive, never deleted, so a write that lands after the last check is kept. `archivedPath` is the verified snapshot and `originalBackupPath` the retained original, present only after its move succeeded. A rename across volumes fails with the source untouched and the verified copy kept; there is no copy-and-delete fallback. A folder stays put, and is reported, if git tracks or has staged any part of it, if the generator owns it, if ownership cannot be determined, or if it holds a link. The archive may not sit inside an active skills tree, which is checked with links resolved before any folder is created and again after. **Deferred, not solved:** an external filesystem change during archive creation can leave an empty directory after a rejected operation. **False refusals on reads (partly fixed).** `.codex/hooks/production-action-guard.mjs` split a search pattern's `|` as if it joined two commands, so a batched read such as `Get-Content package.json; rg -n "SubagentStart|SessionStart" .codex/hooks.json` was refused because `SessionStart` is not a known command. The shared command splitter now treats a separator inside a search tool's double-quoted pattern as data, only where every shell would agree it is quoted. Words beside the pattern are still examined, so `| tee` into a protected file and interpreter writes are still refused. **Not fixed:** the audit's single-quoted `rg -n 'harness|parity|codex|hook|agent' package.json` stays refused. cmd.exe does not treat `'` as a quote and no hook input says which shell runs a command, so each piece could run, even an interpreter executing its stdin. Use double quotes or separate simple reads. **Named limit (conservative by design):** the quote scan is not a shell parser, so anything that could make a shell pair quotes differently turns the double-quoted exception off for the whole command: `$`, `%`, `!`, `#` (so any comment), `<<`, here-strings, a backtick, `\"`, a smart quote, `^` before a quote, a `"` inside single quotes, or quoted text that crosses a line. A batched read with one of those stays refused even when harmless; drop the comment or run the reads separately.
