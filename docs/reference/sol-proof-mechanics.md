# Sol proof mechanics

How a Sol proof is minted, kept, carried and skipped. `.claude/commands/ship.md` says *when* to run Sol; this page says how the proof behaves. The code is `scripts/write-codex-push-proof.mjs` (writer), `.claude/hooks/codex-push-lib.mjs` (`proofValid`, 24 h), `.claude/hooks/sol-accept-lib.mjs` (skips) and `.claude/hooks/migration-landing-gate-lib.mjs` (apply). Where this page and the code differ, the code wins: fix the page.

## The proof

- `node scripts/write-codex-push-proof.mjs`, run bare from the repo root on a clean, committed head. It pins `gpt-6.2-sol` at `high`, reviews in a throwaway folder with no repo instruction files, and writes `.claude/session-state/codex-review-<sha>.json` only on a terminal `CODEX_PROOF_VERDICT: CLEAN`. No proof file for the head = no pass, whatever the exit code. Never hand-write or read back the JSON (`review-proof-guard` blocks both).
- **Base.** A feature branch is reviewed against `origin/staging` (`solTargetRef`); `hotfix/`, `release/`, `main`, `staging`, a detached HEAD, or a missing `origin/staging` use `origin/main`. The base is not a CLI option. Every full run prints `Sol review base: <ref> (commit <sha>)`. The merge gates check the proof's base against GitHub's real base tip.
- **Life.** Bound to one head and one base; valid 24 hours on that head. Any later commit on the Sol list voids it; commits that stay off the list are covered. A base that only moved forward does not void it: the PR may merge behind its base.
- **Base must be inside the head.** Sol refuses when the head lacks the latest base it reviews against (rare: a branch with several split points). Then `git merge <base>`, push, wait for the Codex App, and run Sol; that merge is allowed even though ship.md otherwise merges the base only for a conflict.
- **Quiet-head pre-flight** (cost control; the merge gates re-check all of it). With no PR yet, it notes "no pull request has this commit as its head yet" and reviews. Once a PR exists it refuses, spending nothing, unless the PR is open, non-draft, with this commit as its head; the Codex GitHub App has finished this commit (or 15 minutes passed with none, or the App reviewed none of the last 3 pushes); no Codex App thread on this commit and no CodeRabbit thread on current code is open; CodeRabbit is not mid-review; and a `needs-coderabbit` PR either has no CodeRabbit review yet (Sol may go first) or its review covers this head. It also runs `npm run check:docs`. An unreadable GitHub answer refuses: retry in a minute. `--dry-run` prints the decision.
- **Rounds.** Each full run prints `Sol round N on PR #<n>`. From round 3 it warns about a repeating mechanism (`AGENTS.md` stop rule). From round 5 a full run refuses (`SOL_ROUND_HARD_STOP`) until a decision-log entry names the PR: a new file `docs/manual/decision-log.d/<YYYY-MM-DD>-<slug>.md` whose `## <date> — …` heading is today (Central), never later, with a `**Decision (Mason, <date>)` line recording his OK and `#<PR>`. Push it first: Sol reads the PR head. Never put text in it telling reviewers what not to raise.
- **Applied history.** A full run reads the live ledger (read-only) for each migration file the PR adds. A file whose SQL exactly matches what live stored under that name is shown to Sol as applied history: Sol reviews how other code uses it, not its design. Anything short of an exact match gets the ordinary review. The proof lists such files under `applied_history`.

## Carrying a clean proof to a new head

Each carry mode refuses anything beyond its narrow case; the answer then is a full review. A carried proof says `codex_ran: false`, names where it came from, and expires 24 hours after the original full review at the root of its chain.

| Situation | Command | Allowed only when |
|---|---|---|
| `hotfix/` or `release/` branch merged `origin/main` | `--carry-forward` | The new head is a clean merge of the reviewed head and today's base tip with no hand edits; no renames or copies across the sides; the merge base is the reviewed base; the proof is not owner-accepted. Docs-only on one side with no file overlap carries with no model call; otherwise a focused Sol collision check must return CLEAN. A `DECISION_LOG.md` union merge counts as clean only when both sides only added lines. **Never for a feature branch that merged `origin/staging`**: that needs a new full run. |
| A PR's stamp went stale in the queue (the PR check wants it above the base's newest), or the ordering guard refuses an apply because a newer migration went live | `node scripts/restamp-migration.mjs <old-stamp>` (renames, swaps the stamp in the branch's own files, commits, runs `--carry-restamp`); for a live apply then `node scripts/write-apply-proofs.mjs --restamp-from <old> <new>` | ONE commit on the reviewed head: the `.sql` renamed with the same SQL, except that, in its leading `--` comment header, a line may update its link to its own record (`migrations.d/<stem>.md`) and a line that is only `-- <its name>` or `-- <its name>.sql` moves to the new name; its record renamed with its `SQL sha256` pin set to the new SQL's hash; the old stamp swapped for the new elsewhere; a one-shot data migration's key in `supabase/baselines/one-shot-migrations.json` renamed (that key only; the carry refuses if it still names the old stamp); no other branch migration between the two stamps; nothing else. No model call. The command refuses a migration already on staging or main, a non-feature branch, and a stamp not above both bases. `--restamp-from` still needs byte-identical SQL, so when the command moved a header link or name line, the live apply needs a fresh apply review. Mason's migration approval does not carry: ask again for the new stamp. |
| Records after a live apply | `--carry-post-apply` | ONE commit on the reviewed head holding only: the PR's migration records, `docs/changelog.d/*.md`, `KNOWN_ISSUES.md` / `known-issues.d/*.md`, `.claude/schema-registry.json`, the PR's own stamps in `MIGRATIONS_AWAITING_TYPE_REGENERATION` (`src/lib/rpcContracts.test.ts`), and allowlist re-keys that only swap the hash, append to the justification and bump `dated`. Notes alone carry free; a registry or allowlist change first gets a focused Sol check. Commit the registry here only when the branch contains current `main`; otherwise refresh it in its own PR after the merge. |
| Mason skipped every BLOCKER/HIGH | `--carry-owner-accepted` | See below. Never carries onto a new base. |

## Mason skips Sol findings

When Sol blocks (the round-cap stop, or Mason says so), explain each finding in plain English, saying plainly whether it is a real money, stock, data or security bug and what it could do; never call one minor to get it skipped. He may skip any finding he judges a business call or too small to ever matter.

1. From the PR's clean checkout at the reviewed head: `node scripts/owner-accept-sol-finding.mjs <numbers>`. Make its printed summary, exactly as printed, the whole last message of your turn in the conversation he replies in (any conversation that shows it word for word counts, 2026-11-23).
2. He replies exactly `skip` (all of them) or `skip 1 3` (those), alone on one line (Mason, 2026-11-24, #2271; no reason line, 2026-11-25). Any other reply skips nothing, `yes, <reason>`, `I disagree` and `don't fix` included. The hook prints SKIPPED, or NOT SKIPPED for a reply that starts with skip or yes; other words are ordinary chat and print nothing, so tell him the findings are still open.
3. Fix what he did not skip and run Sol again. Once every BLOCKER/HIGH of the run is skipped: `node scripts/owner-accept-sol-finding.mjs --log`, commit the one file it writes alone (a PR into `staging`: a new `docs/manual/decision-log.d/<date>-pr<n>-sol-skip-<head>.md`; a review against `main`: `docs/manual/DECISION_LOG.md`), then `node scripts/write-codex-push-proof.mjs --carry-owner-accepted`, and keep landing.

The owner-accepted proof covers that exact head of that PR only, for the merge gates and the live apply gate (`migration-landing-gate-lib.mjs` accepts it; a carried repeat skip, below, it never does); the reviewer apply proofs (`write-apply-proofs.mjs`) still need their own clean runs, and a PR that changes gate, hook or approval files cannot use this path. The public log records file, line, a hash of the wording and a fixed sentence, never free text.

**Repeats carry.** A full Sol run on a later head of the same PR into `staging` is shown his skips from the last 7 days and labels each BLOCKER/HIGH `SAME_AS_ACCEPTED <ref>` or `NEW`. When every one is the same (same file, severity not raised, the PR's own change to that file unchanged), do not ask him again: `--log`, the lone commit of the file it writes and `--carry-owner-accepted` record it (mode `owner_accepted_carried`). Claude's staging merge gate accepts that; the live apply gate never does, and Codex hands such a merge to Claude.
