## 2026-11-05 — The Deliveries list can page, search and total in the database (Goal 4, database half)

- New migration `20261130100000_deliveries_list_page.sql` (applied live 2026-11-06, ledger 20261106192100): a new read-only function `get_deliveries_page` returns one page of the Deliveries list (search, status/driver/priority/customer/date filters and every column sort applied in the database, the delivery id as the last sort key) with the true `total_count`, plus the screen's cards and 7-day strip counted over every visible delivery. Every call returns at most 500 rows (`p_limit` NULL is refused); exports and the calendar read pages of 500 by delivery id (`p_after_id`), then sort the rows by each row's `sort_position`. A delivery that matches for the whole read appears exactly once; one cancelled or reactivated while the read is running may or may not appear, and rows near an edit can sit a place out of order (accepted trade-off, Mason 2026-11-06, `docs/manual/DECISION_LOG.md`). SECURITY INVOKER: row level security decides what each person sees, as the screen's own reads do today. A new function plus CHECK `deliveries_id_not_nil` (no delivery id is all zeros, the read-by-id start cursor); grants to authenticated and service_role.
- Proof script `scripts/smoke/prove-deliveries-page-real-schema.mjs` (scratch container, 1,203 deliveries) and live smoke chain `scripts/smoke/smoke-goal4-deliveries-page.sql`.
- The Deliveries screen switches to it in a separate PR after this is live.
