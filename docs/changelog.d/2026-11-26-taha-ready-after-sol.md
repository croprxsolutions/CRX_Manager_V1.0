## 2026-11-26 - A clean Sol now labels our lane PR for Taha automatically

- New `.claude/hooks/taha-ready-after-sol.mjs`: when a clean Sol proof is written, and after a push, `gh pr create` or `gh pr ready`, an open, non-draft lane PR of ours whose current head a clean Sol covers gets `ready-for-taha` and Taha's review request. The Taha ready bot cannot see Sol proofs, and agents kept forgetting the manual step (Mason labelled #2610 by hand). Best-effort: a gh failure prints the manual command and never fails the proof or the push.
- "Covers" is the merge gate's own rule (`proofValidForMerge`): a clean Sol of the current head or of an earlier commit of the PR, so a fix pushed after Sol asks Taha again too (Mason asked to close that gap the same day). Sol runs with findings Mason accepted do not count.
- Proof: `node .claude/hooks/hook-router.test.mjs` (118 assertions); a dry run against the open PRs (label calls intercepted) would have labelled #2643, #2638, #2610 and #2452. #2638 was covered only by a Sol of an earlier commit.
