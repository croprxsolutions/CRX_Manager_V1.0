## 2026-10-21 — Sol carry-forward: a moved main no longer forces a full Sol re-review

Mason approved "go with carry-forward". Every merge into main used to void every waiting PR's Sol proof, because the proof is bound to one head and one base, so parallel sessions kept paying for full Sol reviews again (81 merges to main in the week to 2026-10-21).

- `scripts/write-codex-push-proof.mjs --carry-forward` (with `--dry-run` to print the decision only) keeps an earlier clean Sol review when the new head is exactly the conflict-free merge of the reviewed head and today's origin/main (checked with `git merge-tree`, so a resolved conflict or a hand edit refuses) and that review is under 24 hours old. It carries with no model call when the PR's files and main's new files do not overlap and neither side touches a hot path (`CARRY_HOT_PATHS`: `supabase/`, `.claude/hooks/`, `.codex/hooks/`, `.github/`, the hook settings and the proof-writing scripts) against non-documentation changes on the other side; otherwise it runs a focused Sol collision check (`MAIN_DELTA.patch` + `COLLISION_FOCUS.json`) that centres on the interaction but counts any other blocker it sees, and carries only on CLEAN. A carried source proof must have the full shape the gates accept, and the 24-hour source limit is re-checked just before the proof is written (Luna round 1). The source file is re-read and must be unchanged at write time, a chain of carries expires 24 hours after its original full review, `package.json` and `package-lock.json` are hot paths, and the Codex gate's denial no longer suggests a rebase before a carry (Luna round 2).
- `proofValid()` in `.claude/hooks/codex-push-lib.mjs` accepts the carried shape (`codex_ran: false`, `carried_forward: true`, `carry.mode`, `carry.from_head`, `carry.from_base`) on the same exact-head, exact-base and 30-minute terms. `pr-merge-guard.mjs` prints `SOL CARRY-FORWARD` when it allows one; its and the Codex `production-action-guard.mjs` denials now point at `--carry-forward`.
- Docs: AGENTS.md, `.claude/commands/ship.md`, `/codex-review` Step 3B, `docs/reference/agent-guardrails.md`, `docs/manual/AGENT_ONBOARDING.md` and `docs/manual/DECISION_LOG.md`.
- Tests: carried-proof acceptance and rejection cases in `codex-push-lib.test.mjs`; the decision rules, source-proof rules and an end-to-end throwaway-repository run (clean carry accepted for the new base only, an edited merge commit refused, a stale source refused) in `scripts/write-codex-push-proof.test.mjs`.
- After review: the agent rule files (`AGENTS.md`/`CLAUDE.md` in any folder, `.claude/commands/`, `.claude/skills/`, `.claude/agents/`, `.claude/workflows/`, `.agents/`, `.codex/`, `.husky/`, `.coderabbit.yaml`, `docs/workflows/` and the rule reference pages) are hot paths too, so a new rule on main is checked against a waiting PR (Codex GitHub App P1).
