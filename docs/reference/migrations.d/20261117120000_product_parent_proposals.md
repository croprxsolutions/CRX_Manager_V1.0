What it does:
- New tables, RLS on, `SELECT` only for `authenticated` and no write grant for any role: `product_parent_proposals` (one row per build, one open at a time; admins read), `product_parent_proposal_groups` (one proposed group per row with allow-listed member fields only, no cost, price or stock; admins read; both carry `updated_at`), `product_parent_brands` (a parent's brand list; retired is final), `product_parent_brand_events` (append-only, a trigger refuses update, delete and truncate) and `product_parent_brand_sources` (every moved legacy brand row mapped to one parent brand). - New admin writers, each with `p_idempotency_key` replayed through PAR-1's `_product_parent_replay` and authorized before the replay lookup: `build_product_parent_proposal`, `approve_product_parent_groups`, `hold_product_parent_group`, `reject_product_parent_group`, `upsert_parent_brand`. New read `get_product_brands` (any active user). Eleven private helpers with no API-role EXECUTE.
- Grouping (§5.1): same base name (size, pack and container words removed; strength words such as "4L" kept), same form and, for seed or each, the same stock unit, and never two different EPA numbers. Same EPA number under another name is a flag. A group with some blank EPA numbers, an unreadable EPA number, no form, no name left, or a name that differs from another only by a strength token is held. Building a proposal groups nothing.
- Approval recomputes each group from locked rows and refuses the whole call if anything changed since the build (rate, EPA number, brand, active flag), if a conflict has no exact pick, if an owner-confirmed group lacks the tick, if a tote has no answer, if a shop-filled tote is not fertilizer or not filled from the group's bulk size, if two sizes would be bulk, if the chosen category is retired, or if a size's per-acre prices are not the previewed ones. While rates are locked, a group that would change any size's rate is refused. It copies the picks onto every size through PAR-1's `_copy_parent_to_size` and writes one `created` parent event per group. It never writes EPA numbers or label facts. Legacy brands move to the parent list; identical rows share one parent brand, differing variants need a pick, unpicked variants are kept retired.
- `upsert_product_brand` re-issued (same signature and grants): after the receipt lookup it takes a product-row lock that waits for approval (`FOR NO KEY UPDATE`, which leaves foreign-key checks on that product free) and refuses a grouped size with `PRODUCT_BRANDS_BELONG_TO_PARENT` (nothing written).
