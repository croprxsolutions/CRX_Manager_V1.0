Adds the office call `close_delivery_receipt(p_delivery_id, p_reason, p_idempotency_key)`: `manual_send` pauses a queued customer receipt on the office list right before Email Confirmation emails it by hand, and `handled` closes it (from the "Customer receipts to check" list, or after the hand send went out), so the server sender never emails the customer a copy after the office dealt with it.

**What it does.** For a pending, needs_check, or claimed-but-not-confirmed sending row in `delivery_receipt_queue`: `manual_send` sets `needs_check` (the worker never claims it, and it shows on the office list, so a hand send that fails is not lost), `handled` sets `cancelled` (it leaves the list). Either clears the claim, so the worker's `confirm_delivery_receipt_send` then answers `stale` and sends nothing; `last_error` names who and why, keeping a needs_check row's earlier message once. A row whose send the worker has confirmed, inside its 10-minute lease, is refused with `DELIVERY_RECEIPT_SENDING` (try again in a minute). `manual_send` on a delivery that is no longer completed (voided, reopened or removed) is refused with `DELIVERY_NOT_COMPLETED`, checked before anything else; a retry with a used key (same caller and request only) re-checks the receipt as it is now rather than returning the saved answer, so a retry can never reuse an earlier go-ahead or report a receipt closed that was queued again; a retry whose receipt was re-queued since (the answer's `queued_at` no longer matches) changes nothing and is refused with `DELIVERY_RECEIPT_CHANGED`. A sent row is unchanged (`sent`); no row or a cancelled row answers `none`. Every answer carries `sent_at` and `send_authorized_at` (never the address), so Email Confirmation can ask before sending a copy that may already have gone out. It takes the queue row lock the worker's confirm takes first, so a close and a confirm at the same instant wait for each other and only one wins. Caller: an active admin or sales rep only; every driver is refused (drivers never see Email Confirmation or the office list; Sol HIGH on #1678). The key is required and bound to the caller and request (`check_idempotency_intent`, saved and bound in the same transaction). SECURITY DEFINER, owner postgres, `search_path = public, pg_temp`, EXECUTE for authenticated only. No table, trigger, worker call or existing row changes. A closed receipt whose delivery is later completed again (no send ever authorized) gets a fresh receipt, as `_enqueue_delivery_receipt` already does for a cancelled row.
