## 2026-11-24 - Ingredients: an admin can add a missing CAS on an EPA-numbered product's ingredient

- Migration `20270304150000_ingredient_cas_fill_passes_epa_gate.sql`: re-issues `_edit_active_ingredient` so that an edit of the CAS alone (fill, correct or clear) is no longer refused with `CHEMISTRY_FROM_EPA_ONLY` when a product using the ingredient has an EPA number. Before, an ingredient the EPA lookup added without a CAS (EPA gave none) could never get one; the EPA review itself asks the admin to "correct the ingredient to link them".
- Trust (Mason, 2026-11-25): when EPA gives no CAS, the admin's reason and evidence are trusted. Sol flagged that a mistyped but valid, unused CAS could make a later EPA commit link to the wrong ingredient; Mason accepted that risk. A wrong CAS can be corrected with the same screen.
- Unchanged: the acid fields, or a mix of fields still refuse on an EPA product; admin only; reason and evidence still required when products use the ingredient; CAS format, check digit and CAS-taken checks; the ingredient event and one `corrected` chemistry event per affected product. Product rows (strength, source, modes of action) are not touched.
- Screen: Ingredient review -> Needs CAS -> Add CAS already calls this path; its preview now shows the change instead of "would be refused". The preview's product note reads "has an EPA number" instead of "EPA-confirmed" (the number alone does not mean EPA confirmed the chemistry).
- Proof: `node scripts/smoke/prove-ingredient-cas-fill-epa-gate-real-schema.mjs` (`INGREDIENT_CAS_FILL_PROOF_PASS`, local Docker) and the local test copy in a browser.
- Not verified: the staging database (applied by the staging DB job after merge). Not applied live.
