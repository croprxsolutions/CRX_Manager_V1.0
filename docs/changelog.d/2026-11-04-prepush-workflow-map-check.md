## 2026-11-04 - Pushes check the workflow map is up to date

From the 2026-11-04 retro (KI-93, PR #1459), where a stale `docs/app-workflow-map.html` failed only in CI and cost a round. `scripts/generate-workflow-map.mjs --check` rebuilds the map in memory, never writes the file, ignores the date stamp, and exits 1 with "run `npm run generate-map` and commit" when the committed map is stale. CI's "Workflow map freshness" step now calls it instead of its own sed-and-diff, and `.husky/pre-push` calls it when the push touches `src/`, `docs/reference/rpc-functions.md`, the map, or the generator (`scripts/prepush-needs-build.mjs --map`). Pre-push runs the check on the committed files (each pushed commit, extracted to a temp folder), so a regenerated-but-uncommitted map or an unsaved source edit cannot make a stale committed map pass (Luna and Codex review findings). Other pushes skip it silently. The step takes about 2 seconds.

Proof: in a scratch worktree, a page commit adding an RPC call without regenerating made the real hook exit 1 with the message above and left the map untouched; after `npm run generate-map` and a commit, the map step passed and the hook moved on to the type check. A regenerated but uncommitted map was blocked, and so was a stale commit whose source edit was reverted only on disk. A docs-only push skipped the step. Tests: `scripts/prepush-needs-build.test.mjs` covers the `--map` decision.
