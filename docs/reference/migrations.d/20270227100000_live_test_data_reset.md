## How it works

Preflight on live: every public table locked IN EXCLUSIVE MODE (10-second lock_timeout); refuses with `LIVE_RESET_ALREADY_APPLIED`, `LIVE_RESET_PINS_MISSING`, `LIVE_RESET_SCHEMA_DRIFT` (a public table not in the pins), `LIVE_RESET_COUNT_DRIFT`, `LIVE_RESET_COST_BASIS_FROM_PO` (a kept `product_cost_basis` row points at a PO line through a RESTRICT foreign key) or `LIVE_RESET_GUARD_STATE`. Backup: `CREATE TABLE AS` per deleted table, plus `_inventory_before`, `_customers_before`, `_sequences`, `_triggers_off`, `_manifest`; every grant to PUBLIC, anon, authenticated and service_role revoked. Guards: on each table it deletes from, every user trigger that fires on DELETE (64 on the current schema: the posted, immutable, append-only and lifecycle delete guards, and delete side effects that would write stock, ledger, audit, brand or receipt rows) is switched off by name with `ALTER TABLE ... DISABLE TRIGGER`, only around the deletes, then on again; foreign keys stay enforced. Delete order: `c_core` in the file, children first; jobs, invoices, blend_tickets and field_app_billing_sets reference each other and go in one statement. Sections (constants at the top of the DO block): `c_clear_logs` on, `c_clear_receipts` on, `c_clear_team_notes_on_cleared` off, `c_clear_backup_snapshots` off (Taha confirmed these defaults 2026-11-23). Postflight: cleared tables empty, each section table lost exactly its backed-up rows, every kept table at its pinned count with md5-identical rows (customers apart from prepay_balance_cents, row_version and updated_at; inventory apart from its quantities, last_counted_at and updated_at), every public trigger in its earlier state, prepay 0, stock 0, the six sequences at 0001 next, each backup table equal to what was deleted, the backup unreachable from API roles.

Rollback: a new reviewed migration inserting each table back from `reset_backup_20261123` in reverse delete order (generated columns left out, the same delete and insert guards off), restoring inventory quantities and customer prepay from `_inventory_before` / `_customers_before`, and `setval` from `_sequences`. Keep the schema until Mason confirms the trial data looks right, then drop it in a reviewed migration.
