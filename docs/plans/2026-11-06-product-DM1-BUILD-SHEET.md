Where this sheet and the Stage 2 outline disagree, this sheet wins for DM-1 *how*; the grand plan and Mason's settled decisions (D-A, D-Z, D-AA, D-L, DECISION_LOG) win on *what*. **Words used here.** The Stage 2 sheet's words (parent, size, copied value, pass, harness, retry key) mean the same. Also:
- *Ingredient*: one row in `active_ingredients`, which is always one **specific chemical form** (for example glyphosate isopropylamine salt, or S-metolachlor). A form may name a *canonical parent* (glyphosate acid) and, only where the chemistry allows, a *canonical fraction* (0.741) (D-A).
- *Basis*: what a strength number measures: the form itself (`active_ingredient`) or its acid (`acid_equivalent`); for fertilizer, `oxide` (P₂O₅, K₂O) or `elemental` (P, K).
- *Chemistry*: a parent's ingredient rows, mode-of-action rows and fertilizer analysis rows, all under one `chemistry_version`.
- *Usable EPA number*: a number that is not blank after trimming (grand plan D-Z).

## 3. What DM-1 stores, and the rules it enforces

**Ingredient identity (D-AA, D-A).**
- `active_ingredients` holds one row per specific chemical form: display `name` (never renamed by any resolve or merge, D-AA-4), `name_key` (lower, trimmed, inner spaces collapsed), `cas` (nullable; format and check digit validated in the database; unique among active rows), `canonical_ingredient_id` (nullable self-reference to the parent acid or element), `canonical_fraction` (nullable, finite, `0 < f ≤ 1`), `fraction_basis` (`acid_equivalent` or `elemental`, required exactly when a fraction is present), `status` (`active` or `merged`), `merged_into_id`, `row_version`, who and when.
- **Resolving an ingredient** (every writer, one private helper `_resolve_active_ingredient`): an entry with a CAS uses the active row with that CAS (automatic, D-AA-1), or creates one. An entry with only a name creates a new **provisional** row (no CAS) and, if any active row shares its `name_key`, queues a merge candidate for Mason (D-AA-2). An entry that matches an existing row by CAS or name but names a **different canonical parent** is refused before any write (`INGREDIENT_PARENT_CONFLICT`, D-AA-3, which takes precedence over queuing). An entry may also name an existing ingredient by ID (the screen's picker), which is not a claim and needs no review.
- **Merges** never rewrite chemistry rows. A merge marks the losing row `merged` with `merged_into_id`; every read resolves an ingredient through it (one level only: a merged row cannot be a target, and a target cannot later be merged away while it has merged rows pointing at it, without re-pointing them in the same step). A merge is refused, naming the parents, while any parent carries both ingredients as active rows (settled first through the correction). After a merge, every writer resolves an ingredient ID through `merged_into_id` **before** writing and before every uniqueness check: picking a merged ingredient writes its target, and adding the target to a parent whose existing row points at the merged-away ID is refused as a duplicate. "One active row per (parent, ingredient)" and the mode-of-action "ingredient of the same parent" rule compare resolved IDs. **A merge never changes any parent's numbers silently.** It is refused when the two rows carry **different non-blank CAS numbers** (different chemicals), or disagree on canonical parent (D-AA-3), fraction or fraction basis. When only the losing row has a CAS, the target takes that CAS in the same step, and CAS lookup also follows merged rows to their target, so a later entry with that CAS finds the target and never creates a second row. Those values are settled first through `save_active_ingredient`, which needs reason and evidence and previews every affected parent, and only then can the merge go ahead. Merges happen in exactly two ways:
  - **Name-only candidate** (`active_ingredient_merge_candidates`, status `pending` / `approved` / `rejected`): `decide_ingredient_merge` approves or rejects; this is Mason's side-by-side review in the app.
  - **CAS added to a provisional row that matches another row's CAS**: `save_active_ingredient` refuses unless the call carries `confirm_merge_into` equal to the ID its preview showed. The preview says "this CAS belongs to <name>; saving makes them the same chemical". This is D-AA-1's automatic identity, with the admin's CAS entry as the reviewed act.
- **Fraction edits** on an ingredient that any parent uses change cost for every such parent, so changing an established `canonical_ingredient_id`, `canonical_fraction`, `fraction_basis` or `cas` needs a reason and evidence; filling a blank one does not. Every change appends to `active_ingredient_events`.
- **"Needs CAS" worklist**: every active provisional ingredient, with the parents using it (`get_active_ingredient_worklist`). Retyping a name already on the list instead of picking it creates another provisional row and candidate (D-AA-2 allows no name-only identity); the screen's picker offers the existing name first to keep that rare.
- **Acid-equivalent strength needs a canonical parent.** A strength stated on the `acid_equivalent` basis is refused unless the form names a canonical parent (the acid it is measured as), or the form is itself the acid (no canonical parent, `fraction_basis` NULL, and the screen labels it "acid").

**A parent's chemistry** (all rows keyed to the parent; `retired` rows keep their history and are excluded from every live read and from cost):
- `product_parent_ingredients`: `id`, `parent_id`, `ingredient_id` (the specific form), `strength_value numeric` (finite and > 0; at most 100 for `pct_ww` and at most 20 for `lb_per_gal`; NULL exactly when `strength_unknown`), `strength_unknown boolean`, `strength_unit` (`pct_ww` or `lb_per_gal`), `strength_basis` (`active_ingredient` or `acid_equivalent`), `source` (`label`, `sds`, `supplier`, `other`), `source_note`, `status`, who and when. One active row per (parent, ingredient). `lb_per_gal` is refused on a dry parent. Zero strength is refused (an ingredient at 0 is not an ingredient); unknown is its own state. % w/v is not stored: the entry asks for the label's lb/gal, which US labels state (a % w/v-only label is entered as unknown strength with the note).
- `product_parent_modes_of_action`: `parent_id`, `ingredient_id`, `scheme` (`HRAC`, `FRAC`, `IRAC`), `group_code` (trimmed text, ≤ 10), `status`, who and when created and last changed; unique on the four (active rows). The ingredient must be an active ingredient row of the same parent.
- `product_parent_fertilizer_analysis`: `parent_id`, `nutrient` (fixed list: N, P, K, S, Ca, Mg, B, Cl, Co, Cu, Fe, Mn, Mo, Ni, Zn), `basis` (`oxide` allowed only for P and K; otherwise `elemental`), `percent numeric` (% w/w, finite, > 0 and ≤ 100) or `unknown`, `source`, `source_note`, `status`, who and when created and last changed; one active row per (parent, nutrient, basis). A label's P₂O₅ is stored as P on the `oxide` basis; it is never silently converted on save.
- **Biologicals** store no CFU count (Mason, 2026-10-29): there is no CFU column. Any other registered active a biological carries is an ordinary ingredient row, with strength unknown where the label gives none.
- `product_parent_chemistry_state(parent_id PK, chemistry_version bigint, updated_by, updated_at)`: created on a parent's first chemistry write (version 0 means "no chemistry yet"). Every chemistry write, correction and (later) proposal is bound to it.
- `product_chemistry_events`: append-only (update, delete and truncate refused, like `product_parent_events`): `parent_id`, `event_type` (`set`, `corrected`), `chemistry_version` after, `reason`, `evidence`, `before_values`, `after_values`, who and when.

**Add versus correct (DECISION_LOG 2026-10-30 correction rule, as PAR-1's identity correction).** `set_parent_chemistry` may only **add** a row (ingredient, mode of action, nutrient) or **fill** a strength or percent that is unknown. Changing an established strength, unit or basis, changing a source, retiring a row, or swapping one ingredient for another is refused there (`CHEMISTRY_CHANGE_NEEDS_CORRECTION`) and goes through `correct_parent_chemistry` with reason and evidence after its preview shows old and new values and every size of the parent.

**EPA gate (D-Z, per registration), one shared helper.** `_parent_chemistry_epa_refusal(p_parent_id) RETURNS text` returns NULL when the parent may take typed chemistry, or a named refusal listing each usable number found on: the parent's generic number, any member size's `epa_registration`, any active parent brand, and any legacy `product_brands` row of a member size. **In DM-1 it refuses whenever any usable number exists** (`CHEMISTRY_FROM_EPA_ONLY: this product has EPA number(s) …; its chemistry comes from the EPA auto-fill`). Both `set_parent_chemistry` and `correct_parent_chemistry` call it (Stage 2 sheet 7.8, round-8 MED: one gate in one helper), and DM-1b's workbook path and DM-4's commit later call the same helper. **The failed-lookup exception is DM-4's**: DM-4 re-issues this helper to let a number through only when its failure row carries the lookup ID, the registration version from REG-1 and the parent link it was bound to, with no later success or open proposal for that number (7.8, "DM-1 / DM-1b" row). DM-1 creates no failure table. Chemistry already stored when a parent later gains a number (a new brand, or the 7.7 correction) stays live and readable (D-L: typed chemistry is never overwritten); further typed changes are refused until the number is cleared or DM-4 supplies them.

**Serialising the gate with brand and number writers.** Every chemistry writer (and `set_parent_cost_reference`) locks in this order: the parent row `FOR NO KEY UPDATE`; then its member `products` rows `FOR SHARE` in product-ID order; then the chemistry state row, created if missing with `INSERT … ON CONFLICT (parent_id) DO NOTHING` (version 0) and then locked with `SELECT … FOR UPDATE`, so two concurrent first writes serialise and the second gets `CHEMISTRY_STALE`, never a raw duplicate-key error; then the ingredient-list advisory lock (`pg_advisory_xact_lock(hashtext('crx.active_ingredients'))`). It evaluates the gate only after those locks.
- The parent lock `FOR NO KEY UPDATE` conflicts with the `FOR SHARE` that `upsert_parent_brand` takes on the parent (`20261123120000:1157`), so a parent brand is serialised even on a parent with no sizes (a parent can be left with none, because moving its last size away is allowed).
- The member `FOR SHARE` conflicts with the `FOR NO KEY UPDATE` that the legacy `upsert_product_brand` takes on the size row (`:1329-1331`) and with every PAR-1 parent writer's `FOR UPDATE`.
- So a number added concurrently either commits first (and the gate sees it) or waits for the chemistry write.
- **No deadlock cycle.** PAR-1 parent writers and `upsert_parent_brand` take the parent first, then members in ID order, the same order as here. `upsert_product_brand` and PAR-2's group approval lock only product rows and never lock an existing parent's row afterwards, so they cannot hold a size while waiting for a parent this writer holds.
- **No size can join a parent behind the gate's back.** PAR-2's group approval only ever inserts a **new** parent and puts the sizes there (`_approve_product_parent_group`, `20261123120000:1059-1074`), so it never adds a size to a parent a chemistry writer is checking. PAR-1's `add_product_size` and `move_product_size` lock the target parent `FOR UPDATE`, which waits for this writer's `FOR NO KEY UPDATE`.
- Ingredient writers and merge decisions take only the ingredient-list lock, which every chemistry writer takes last. Because of that, and because inserts run in sorted (CAS, then name key) order inside one transaction, they cannot deadlock against a chemistry writer. That also satisfies D-AA-4's "deterministic order".

**Reads.** Chemistry is not cost: `get_parent_chemistry(p_parent_id)` and `search_active_ingredients(p_text)` are open to active users (no key; no cost or price). Cost is admin-only in the database (below).

**Saved records.** No saved quote, order, job, blend ticket, invoice or document stores or prints chemistry today, and DM-1 adds none; cost per lb of active is a live admin view. So a correction cannot rewrite history. Any later package that prints ingredient amounts on a saved record must snapshot them there (unchanged from the outline).

## 4. CMP-1 · cost per lb of active

**One figure per active ingredient and basis, per generic** (DECISION_LOG 2026-10-28 Q4, 2026-10-15, 2026-10-22). A premix has one figure for each active, each costed against the whole product's price; pounds of unlike actives are never added.

**Reference size.** The parent's figures are its reference size's. The reference is the parent's **active** `bulk` member when it has one. Otherwise it is the size an admin picks in `product_parent_cost_reference(parent_id PK, reference_product_id, row_version, set_by, set_at)` through `set_parent_cost_reference`:
- admin only, with a retry key and expected version;
- uses the section 3 lock order;
- refused while the parent has an active bulk member, since an active bulk size always wins;
- an inactive bulk size does not block picking. The parent figure is refused by name while the reference is unset, inactive or no longer a member (a move or deactivation clears nothing; the figure stops until an admin picks again). Every size's own figure is listed beneath as detail; sizes are never averaged.

**The math** (one private function, `_parent_active_cost_rows(p_parent_id)`; exact `numeric` throughout; one rounding, half-up to whole cents, on each final figure; no intermediate rounding):
1. **Cost per gallon or per lb.** `current_cost` is dollars per the size's `inventory_unit`. A liquid size: `cost_per_gal = current_cost × 128 ÷ liquid_oz(inventory_unit)`. A dry size: `cost_per_lb = current_cost × 16 ÷ dry_oz(inventory_unit)`. `liquid_oz` and `dry_oz` come from one new private helper `_unit_factor_oz(p_unit, p_unit_type)` with BLK-1a's rule (case-insensitive, that `unit_type`, `0 < factor < ∞`, NULL when spellings disagree). A count unit (`Ea`, `Unit`), an unknown unit, or a cost that is missing, zero, negative, non-finite or not whole cents (`current_cost` is a legacy numeric-dollar column, so it is checked on read and never rounded into shape; DM-1 never writes it, so a whole-cent `CHECK` on `products.current_cost` stays with the products owners and is not added here), or a `seed` / `each` parent is refused by name per size. A size priced per `MG` is also refused by name (`UNIT_UNCONFIRMED: priced per milligram; confirm the unit first`) until Mason answers question 2. *shortcut: count-unit sizes are refused because none is active today; a count unit would need a net weight per unit, which no package defines yet, so that is a new interface to add when one appears.*
2. **Pounds of active per gallon or per lb.**
   - Liquid, `lb_per_gal`: the stated value.
   - Liquid, `pct_ww`: `value ÷ 100 × lb_per_gal`, where `lb_per_gal` is the parent's **approved** weight per gallon from DM-2 (interface below). None approved: refused (`DENSITY_NOT_APPROVED`).
   - Dry, `pct_ww`: `value ÷ 100`.
   - Fertilizer analysis: the same, with the row's percent (always % w/w).
   - Unknown strength or percent: refused for that row.
3. **Cost per lb of active** = step 1 ÷ step 2, per row, on the row's own basis.
4. **Conversions** (one function, `_chemistry_convert(p_value, p_from_basis, p_ingredient_id or p_nutrient)`, returning either a number or a refusal reason, never a bare nullable; Stage 2 / August R-4a): an `active_ingredient` strength also yields an `acid_equivalent` figure when its form has `fraction_basis = 'acid_equivalent'` and a fraction (`lb_ae = lb_ai × fraction`); a fertilizer `oxide` row also yields an `elemental` figure with the fixed factors **P₂O₅ → P × 0.4364** and **K₂O → K × 0.8301** (stated in the migration; P/P₂O₅ = 61.95/141.94, K/K₂O = 78.20/94.20). Never the reverse; never across forms; an isomer (S-metolachlor) is its own ingredient by CAS, and a NULL fraction refuses any numeric conversion. A refusal is returned as that figure's reason; no `COALESCE(fraction, 1)` exists anywhere (a mutation case proves it).

**RPC.** `get_parent_active_costs(p_parent_id)`: `SECURITY DEFINER`, admin-only (`ADMIN_REQUIRED` before any read; a non-admin receives nothing), read-only, no key. Returns the reference size, the parent figures, and per size: priced unit, cost per gal or lb, and per row its figure in cents or its refusal reason, plus the converted figures. Every figure is labelled "from catalog cost" and carries the approved weight-per-gallon row ID it used.

**DM-2 interface (defined here; DM-2 provides the body).** One private function, no grants:
`_approved_parent_lb_per_gal(p_parent_id uuid, OUT lb_per_gal numeric, OUT weight_row_id uuid)`, `STABLE SECURITY DEFINER SET search_path = public, pg_temp`, owned by `postgres`: with `REVOKE ALL … FROM PUBLIC, anon, authenticated, service_role` stated by whichever migration creates it and repeated by DM-2's replacement, so no caller can run it directly. It returns the parent's one **approved** weight per gallon and its row ID, or NULL for both when there is none (a draft never counts). Whichever of DM-1 and DM-2 applies first creates it: DM-1's migration creates it only when `to_regprocedure` finds none, with a body returning NULL (so every % w/w liquid figure refuses with `DENSITY_NOT_APPROVED` until DM-2); DM-2's migration `CREATE OR REPLACE`s it with the real body and keeps the signature. The DM-1 harness proves both orders (stub, then a stand-in approved value). DM-2's sheet adopts this name and signature, or both sheets are changed together before either database PR is built. ## 5. Database PR: migration `<stamp>_product_chemistry`

**Changes to existing objects (no grant, revoke or policy change):**
- `ingredient_map`: a `BEFORE INSERT OR UPDATE OR DELETE` row trigger and a `BEFORE TRUNCATE` statement trigger, both calling `refuse_ingredient_map_write()` (`INGREDIENT_MAP_RETIRED: the Brand vs Generic list is read-only; record ingredients on the product's Chemistry section`). Old browsers are refused too. Its grants and policies stay exactly as they are (Mason-gated to change; not needed).

**Private helpers** (no grants): `_resolve_active_ingredient`, `_ingredient_cas_valid`, `_parent_chemistry_epa_refusal`, `_lock_parent_chemistry` (the lock order in section 3; returns the current version and refuses a stale expected version with `CHEMISTRY_STALE`), `_parent_chemistry_values` (the full chemistry as the event log records it), `_apply_parent_chemistry` (the one writer every public chemistry RPC and, later, DM-4 and DM-1b call inside their own transaction, with no key of its own), `_unit_factor_oz`, `_chemistry_convert`, `_parent_active_cost_rows`, and `_approved_parent_lb_per_gal` (created only when absent; section 4).

**RPCs** (all `SECURITY DEFINER`, `SET search_path = public, pg_temp`, owned by `postgres`; `REVOKE ALL … FROM PUBLIC, anon, authenticated, service_role`, then `GRANT EXECUTE … TO authenticated` for the public ones). Every writer: admin-only, checked **before** the replay lookup; retry key required and fingerprinted through `_product_parent_replay` (actor and request bound; a NULL key, a different caller or a changed request under one key is refused); receipt saved with `save_idempotency` last in the same transaction.
- `set_parent_chemistry(p_parent_id, p_expected_chemistry_version, p_changes jsonb, p_idempotency_key)`: adds rows and fills unknown values only (section 3), all-or-nothing for one parent. It takes no reason: adding or filling a blank needs none, the same as PAR-1's first rate entry. The outline's `p_rows` is renamed `p_changes`, because the call also carries mode-of-action and fertilizer entries. `p_changes` is a list of `{kind: ingredient | mode_of_action | fertilizer, …}` entries; an ingredient entry names `ingredient_id`, or `{name, cas, canonical_ingredient_id, canonical_fraction, fraction_basis}` for a new form. Runs the lock order and the EPA gate, then writes one `set` event and bumps the version. Refuses an inactive parent and an empty change.
- `preview_parent_chemistry_correction(p_parent_id, p_changes jsonb)` (admin, read-only): old and new values per row, every size of the parent, the gate's result, and the current version.
- `correct_parent_chemistry(p_parent_id, p_expected_chemistry_version, p_changes jsonb, p_reason, p_evidence, p_idempotency_key)`: changes, retires or swaps rows; reason and evidence required; same locks and gate; refuses an inactive parent; one `corrected` event.
- `preview_active_ingredient_change(p_ingredient_id, p_fields jsonb)` and `save_active_ingredient(p_ingredient_id, p_expected_row_version, p_fields jsonb, p_confirm_merge_into uuid, p_reason, p_evidence, p_idempotency_key)`: creates an ingredient (`p_ingredient_id` NULL) or edits one; reason and evidence required to change an established CAS, canonical parent, fraction or basis; the CAS-match merge rule in section 3; never renames another row.
- `decide_ingredient_merge(p_candidate_id, p_expected_from_version, p_expected_into_version, p_decision, p_reason, p_idempotency_key)`: `approve` or `reject` a name-only candidate; refused when either ingredient changed since the list was read, when the canonical parents disagree (D-AA-3), or while any parent carries both.
- `set_parent_cost_reference(p_parent_id, p_reference_product_id, p_expected_row_version, p_idempotency_key)`: the size must be an active member; refused while the parent has a bulk member.
- Reads: `get_parent_chemistry(p_parent_id)` and `search_active_ingredients(p_text, p_limit default 50)` (active users only: each calls `is_active_profile()` first and refuses otherwise, because a `SECURITY DEFINER` read bypasses table policies); `get_active_ingredient_worklist()` (admin: provisional ingredients and pending candidates, side by side); `get_parent_active_costs(p_parent_id)` (admin; section 4).

**Grants summary:** new tables: `SELECT` policies only (one admin-only). Pass or private tables: none needed (DM-1 writes no copied value on `products`, so it uses no pass). Public RPCs: `EXECUTE` to `authenticated`. Existing objects: two triggers on `ingredient_map`; no grant, revoke or policy change on an existing table, so **no `I approve`.**

## 7. Done when (harness, then the private test copy)

**Harness** (`scripts/smoke/prove-product-chemistry-real-schema.mjs`, seeded rows that copy real shapes; no live rows):

Rounding: one half-up to cents, shown on a case that lands on half a cent.
- **Refusals by name:** a count-unit size; an unknown unit; a missing or zero cost; unknown strength; zero strength; `lb_per_gal` on a dry parent; % w/w liquid with no approved weight (stub in place, and again with only a draft weight when DM-2 is live); a NULL fraction; a reference that is unset, inactive or moved away; a `seed` / `each` parent.
- **Mutation case:** removing the fraction from the IPA salt makes the ae figure a refusal, never the ai number.
- **Gate (D-Z):** a parent with a generic number, with a member size number, with an active parent brand number, with a legacy brand number on a member size, and with a retired parent brand only: the first four refuse both `set_parent_chemistry` and `correct_parent_chemistry`, the last is allowed. A legacy brand number added in a second session while the chemistry write holds its locks either commits first (write refused) or waits (write succeeds, then the brand saves): never both.
- **Add versus correct:** adding an ingredient and filling an unknown strength succeed through `set_parent_chemistry`; changing a strength, basis or source, retiring a row or swapping an ingredient is refused there and succeeds through `correct_parent_chemistry` with reason and evidence; missing reason or evidence is refused. A retired row is excluded from reads and cost and kept with its history.
- **Identity (D-AA):** two writes naming one CAS under two names resolve to one ingredient; two name-only entries with one normalized name create a pending candidate, never a merge; a name or CAS match claiming a different canonical parent is refused with zero writes; approving a candidate marks the loser merged and every read shows the target; a merge is refused while a parent carries both; a CAS added to a provisional row that matches another is refused without `confirm_merge_into` and merges with it; no resolve or merge renames a row. Two concurrent first-time entries of one new CAS create one ingredient.
- **Identity edges:** a merge between two rows with different CAS numbers is refused; after a merge where only the loser had a CAS, a new entry with that CAS resolves to the target.
- **Inactive users:** a deactivated user calling `get_parent_chemistry` or `search_active_ingredients` gets a refusal and no data.
- **Units:** a size priced per `MG` is refused with `UNIT_UNCONFIRMED`; a count-unit size is refused by name.
- **Private helper:** `_approved_parent_lb_per_gal` cannot be executed by `anon`, `authenticated` or `service_role` (read back from the catalog after both the stub and the replacement).
- **Bad numbers:** a NaN or infinite strength, percent or fraction, `pct_ww` over 100, and `lb_per_gal` over 20 are refused by the table. A price that is negative, non-finite or not whole cents gives a named refusal for that size. A merge between forms with different fractions is refused.
- **Concurrency and merges:**
  - Two concurrent first chemistry writes on one parent: one succeeds, the other gets `CHEMISTRY_STALE`, never a duplicate-key error.
  - A parent brand number added concurrently on a parent with no sizes: either the brand commits first and the chemistry write is refused, or the chemistry write succeeds and then the brand saves.
  - Picking a merged ingredient writes its target.
  - Adding the target ingredient where a row points at the merged-away ID is refused as a duplicate.
  - An `acid_equivalent` strength on a form with no canonical parent that is not marked as the acid is refused.
  - An inactive bulk size lets an admin pick the reference.
- **Every writer:** a non-admin call writes nothing; a direct insert, update or delete on every new table is refused; a NULL key is refused; one key twice writes once; one key with a changed request is refused; a stale `chemistry_version` or `row_version` is refused by name.
- **Cost is admin-only:** `get_parent_active_costs` and the reference table return nothing to a sales rep.

## 8. Risks

- **A wrong cost per lb of active from a unit or basis mistake.** Guarded by one conversion function that can refuse, the hand-checked cases above, and the per-figure label showing which weight row and priced unit it used. The two `MG`-priced products are the known data risk (section 9).
- **An unreviewed or EPA-sourced value typed in.** Guarded by the database gate (one helper for every path) and the add-versus-correct rule. Agents never enter chemistry through the product page: agent drafts (DATA-5) wait for DM-1b's proposals or DM-4's lookups, both reviewed before they write.
- **A wrong merge.** Only CAS matches merge without a click, and a CAS typo is caught by the check digit and by the preview's merge sentence; merges change no chemistry row, so a wrong one is reversible by a reviewed migration that clears `merged_into_id`.
- **The ingredient-list lock serialises all chemistry writes.** Acceptable: admin-only, low volume. Named so a later bulk path (DM-1b) batches inside one lock.
- **DM-2 interface drift.** If DM-2's sheet chooses another name or signature, both sheets change together before either database PR is built; the DM-1 harness proves the stub-then-real order.

**Sol list:** yes, both PRs (`supabase/`; `ProductDetail.tsx`). **Mason-gated:** none at apply (no live rows written, no existing-table grants). Live data steps are Mason's: name-only merge decisions and review of any drafted chemistry (DATA-5, through DM-1b or DM-4).
