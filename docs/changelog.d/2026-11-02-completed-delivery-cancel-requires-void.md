## 2026-11-02 — A completed delivery can no longer be cancelled; it must be voided (local candidate)

Migration `20261102140000_completed_delivery_cancel_requires_void.sql` changes the two private bodies behind `cancel_delivery` and `batch_cancel_deliveries`. A direct, stale or offline-queued cancel of a `completed` delivery, by an admin or a sales rep, is now refused with `DELIVERY_COMPLETED_USE_VOID` after the delivery row is locked. Undoing a completed delivery goes only through the admin-only `void_delivery`, which carries its closed-month warning and audit trail. Batch cancel re-reads each delivery under that lock and skips anything no longer scheduled or in progress, so a delivery completed after the list was loaded is skipped rather than failing the batch. Scheduled, in-progress and quick-delivery cancels, idempotency, and replay of stored receipts are unchanged. The cancel body's forged-actor refusal gains the `ACTOR_MISMATCH` token.

Screens: the batch-cancel toast and activity log report the count the server cancelled (with a warning when some were skipped); Delivery Detail offers Cancel only on scheduled and in-progress deliveries (it had shown it on voided ones); the new refusal reads "This delivery is already completed, so it cannot be cancelled. An admin can void it instead".

Proof: `scripts/smoke/prove-completed-delivery-cancel-requires-void-real-schema.mjs` replays the baseline and every post-baseline migration in a disposable container and runs the same matrix before and after the candidate (admin and rep refused with no stock, stock-movement, invoice, delivery, order or order-line change; mixed and stale batches skip the completed delivery; every other case identical; a receipt stored before the candidate still replays; grants unchanged; a second apply refused). Not proven: two sessions racing a completion against a batch (the lock makes it safe by construction, but no concurrent test was run). A live read-only check on 2026-11-02 found 22 cancelled deliveries, none ever completed, and no `cancelled_delivery_reversal` stock movements, so no data repair is needed. This candidate has not been applied to production.
