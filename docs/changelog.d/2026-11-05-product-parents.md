## 2026-11-05 — Product parents: one record per formulation (PAR-1, database)

Migration `20261108120000_product_parents.sql` (applied live 2026-11-05). Database part only; the Parent panel, read-only size fields and Duplicate buttons come in the follow-up screens PR, opened once this is live. A parent holds what is the same for every size of one formulation: name, nickname, form, formulation type, safener, generic EPA number, category, use timings and rates. Each size stays an ordinary product with its own ID, SKU, price, stock, vendor links and notes. The parent copies its category, use timings and rates onto every size in the same step, so every existing screen keeps reading them from the size, and a guard refuses changing those (or the EPA number) on one size alone, naming the parent and telling the user to reload. Admin-only, retry-safe database functions create a product with its parent, add a size, edit a parent, set or (while rates are locked) correct a parent's rates for every size at the previewed per-acre prices, move a misgrouped size with a reason and evidence, and correct a parent's formulation type or safener (EPA-number correction stays off until REG-1). Every parent change is in an append-only log, and each size change it causes appears in the product's history as a parent copy linked to that log entry. No product has a parent until one is created, so applying this changes no existing product, price or open Setup-tab download. Proof: `scripts/smoke/prove-product-parents-real-schema.mjs`.
